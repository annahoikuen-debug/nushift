# 🧸 配置基準連動型 シフト自動作成AI

園児の登降園予定と保育所の**職員配置基準**から、必要な人員を時間帯ごとに算出し、
労働基準法と職員ごとの契約・希望を守ったシフトを MILP（PuLP / CBC）で自動作成するツールです。
ブラウザで操作する GUI（Streamlit）と、ブラウザ無しで完結する CLI の両方を用意しています。

```
園児CSV/Excel  ─┐
職員CSV/Excel  ─┼─→  配置基準エンジン  ─→  MILP ソルバ  ─→  過不足/法令検査  ─→  CSV/Excel/ICS
希望休CSV     ─┘     (誰がいなければ)      (誰がいつ働く)      (守れているか)      ＋ZIP
```

- 必要人員の**根拠（basis）**を全セルに持たせ、「なぜこの人数が必要か」を文字列で説明できます
- 2名ルール・延長保育の代替措置・短時間保育 ONLY 園など、自治体ごとのプリセットに対応
- 労働基準法（休憩 45/60 分・休息 11 時間・法定の枠組みは月 45 時間・年 360 時間）
  と、本アプリが内部で使う厳しい側の目安（週 44 時間）と
  契約（週契約時間・1日上限・週最大出勤日数・連続勤務上限）を**ハード制約**として扱います
- 希望休・出勤不可はハード制約、稼働時間の偏りはソフトペナルティで調整します

### 機能2: 必要人員の「根拠」を文字列として取り出す

本ツールの中心的な機能が **need traceability（必要人員の根拠）** です。
`Requirement` は計算結果（`needed_staff`）に加えて、`basis` という日本語の説明文を必ず持ちます。

```bash
# 出力された「根拠」列を含む先頭 3 行を見る
head -4 out/requirements.csv
```

```console
$ head -4 out/requirements.csv
日付,表示日付,時間帯,開始,終了,年齢クラス,在園児数,必要人員,必要保育士数,時間帯区分,根拠,必須
2026-09-30,9/30(水),07:00-07:30,07:00,07:30,0歳児,1,1,1,早朝保育,0歳児 1名 ÷ 3 = 1名（定員比3:1、切り上げ）／早朝保育（保育標準時間前）,True
2026-09-30,9/30(水),07:00-07:30,07:00,07:30,5歳児以上,1,1,1,早朝保育,5歳児以上 1名 ÷ 12 = 1名（定員比12:1、切り上げ）／早朝保育（保育標準時間前）,True
2026-09-30,9/30(水),07:30-08:00,07:30,08:00,0歳児,1,1,1,早朝保育,0歳児 1名 ÷ 3 = 1名（定員比3:1、切り上げ）／早朝保育（保育標準時間前）,True
```

延長保育の時間帯では、代替措置が `basis` に明記されます。

```console
$ grep "延長保育" out/requirements.csv | head -1
2026-09-30,9/30(水),17:00-17:30,17:00,17:30,0歳児,6,2,1,延長保育,0歳児 6名 ÷ 3 = 2名（定員比3:1、切り上げ）／保育標準時間外（延長保育）／延長保育の代替措置（保育士1名＋支援員）で必要保育士数を1名に緩和,True
```

この 1 行に **在園 6 名 → 必要人員 2 名 → 必要保育士数 1 名に緩和** という
3 段階の判断がすべて分かります。`必要保育士数` が `2` ではなく `1` になっているのは、
福岡市の代替措置（延長 18:30 まで保育士 1 名＋他資格者で可）のおかげです。

`根拠` 列を読むだけで、**なぜこの人数が必要か**が計算の途中経過まで分かります。
区切り記号 `／` は左から順に「定員比での割り算」「時間帯区分」「追加の措置」を表します。
GUI のタブ 2「必要人員」では、この文字列がそのまま各セルの説明として表示されます。

### 機能3: 自治体プリセットで必要人員が変わる

同じ園児データでも、自治体基準を変えると必要人数が変わります。
5 名の 1 歳児が保育標準時間帯に在園する場合の実際の比較結果です。

```bash
shiftai presets           # 11 種類の一覧と出典を表示
shiftai presets --json    # JSON で取得
```

```console
$ shiftai presets
[全国基準（厚労省）] 全国基準（厚労省）
    厚労省告示第49号の標準。4・5歳児20:1・延長は保育士のみ
    出典: 保育所の職員配置基準（昭和52年厚生省告示第49号）・保育所保育指針
[大阪市] 大阪市
    0歳児4:1・1歳児5:1・2歳児7:1と厳しめ、延長18:30まで代替措置可
    出典: 大阪市「保育所の職員配置基準」告示／大阪市保育已基本方針
[福岡市] 福岡市
    1歳児4:1、延長18:30まで保育士1名＋他資格者で代替可（19:00以降は保育士のみ）
    出典: 福岡市「保育所の職員配置基準」告示／福岡市保育已基本方針
...
既定の基準は 全国基準（厚労省） です（--standard で変更できます）。
```

同じ入力を 3 つの基準で走らせた結果（`basis` の差分だけ抜粋）:

| 基準 | 必要人員 | `basis` |
| --- | ---: | --- |
| 全国基準（厚労省） | 2名 | `1歳児 5名 ÷ 6 = 1名（定員比6:1、切り上げ）／保育標準時間／2名ルールによる底上げ` |
| 福岡市 | 2名 | `1歳児 5名 ÷ 4 = 2名（定員比4:1、切り上げ）／保育標準時間` |
| 保育標準時間のみ園 | 2名 | `1歳児 5名 ÷ 6 = 1名（定員比6:1、切り上げ）／保育標準時間／2名ルールによる底上げ` |

全国基準と福岡市で**同じ「2 名」でも算出理由が違います**。

- 全国基準は `5 ÷ 6 = 1名`（切り上げ）で 1 名ですが、**2名ルールで底上げ**されて 2 名になる
- 福岡市は `5 ÷ 4 = 2名`（切り上げ）で、最初から定員比で 2 名になる

つまり「2 名必要」は、全国基準と福岡市では**根拠が違う**と分かります。
これが、このツールが「必要人数」だけでなく「その理由」まで持つ理由です。

> **注意**: プリセットの数値は一般的な実務水準に基づく目安です。
> 実際の運用では必ず自治体の告示・条例・要綱への個別確認を行ってください。

### 機能4: CLI でヘッドレス実行して成果物を揃える

ブラウザなしで完結します。バッチやスケジュール実行に向いています。

```bash
# 実データで実行する例
shiftai solve \
  --children  data/children.csv \
  --staff     data/staff.csv \
  --preferences data/preferences.csv \
  --standard  福岡市 \
  --start 2026-10-01 --end 2026-10-07 \
  --open 09:00 --close 14:00 --granularity 30 \
  --out out --zip --strict
```

終了コードは CI でそのまま使えます。

| コード | 意味 |
| --- | --- |
| 0 | 正常終了（法令違反なし） |
| 1 | 入力・実行エラー |
| 2 | 法令違反（BLOCKER）が 1 件以上 |
| 3 | `--strict` 指定時かつ要調整（WARNING）が 1 件以上 |

```console
$ shiftai solve --sample --out out --strict --time-limit 30 >/dev/null 2>&1
$ echo $?
3        # 要調整（WARNING）があるので --strict で失敗扱い
```

### 機能6: 過不足と法令違反の検査（21 コード）

生成したシフトを**独立に検査**します。ソルバの制約と別の実装なので、
「モデルが守ったはずの制約」を別の経路で再検証できます。

```bash
# 過不足を時間帯ごとに見る
head -4 out/gap.csv
```

```console
$ head -4 out/gap.csv
日付,時間帯,開始,終了,時間帯区分,必要人員,必要保育士数,配置人員,配置保育士数,不足,不足保育士数,過剰
2026-09-30,07:00-07:30,07:00,07:30,早朝保育,2,2,2,2,0,0,0
2026-09-30,07:30-08:00,07:30,08:00,早朝保育,2,2,2,2,0,0,0
2026-09-30,08:00-08:30,08:00,08:30,早朝保育,7,7,7,7,0,0,0
```

違反は深刻度 3 段階（`BLOCKER` / `WARNING` / `INFO`）で分類されます。
`BLOCKER` は法令違反、`WARNING` は運用上の要調整、`INFO` は参考情報です。

| 分類 | コード例 | 意味 |
| --- | --- | --- |
| 法令違反 | `SHORTFALL_STAFF` | 必要人員が不足している |
| 法令違反 | `SHORTFALL_QUALIFIED` | 必要保育士数が不足している |
| 法令違反 | `REST_HOURS_SHORT` | 勤務間休息が 11 時間を下回る |
| 法令違反 | `BREAK_INSUFFICIENT` | 休憩が法定時間（45/60 分）に満たない |
| 法令違反 | `MONTHLY_HOURS_EXCEEDED` | 月間 45 時間の上限を超過 |
| 要調整 | `WEEKLY_DAYS_EXCEEDED` | 契約の週最大出勤日数を超過 |
| 要調整 | `CONSECUTIVE_DAYS` | 契約の最大連続勤務日数を超過 |
| 要調整 | `SPLIT_SHIFT` | 勤務が複数のブロックに分かれている |
| 要調整 | `BREAK_FRAGMENTED` | 休憩が分断されている |
| 要調整 | `STATUTORY_DAILY_HOURS` | 法定の日勤上限（8h+45min）を超過 |
| 参考 | `HOURS_IMBALANCE` | 職員間の勤務時間偏りが大きい |
| 参考 | `BREAK_OVERLAP` | 同時休憩者が在勤者数の 25% を超過 |

 違反 21 種すべてのコードと説明は [`docs/02_ソルバ仕様.md`](docs/02_ソルバ仕様.md) にあります。

検査は GUI のタブ 3「シフト作成」の違反一覧にも同じものが出ます。
深刻度によって色分け（赤＝法令違反、黄＝要調整、灰＝参考）されます。

### 機能7: Python API として使う

CLI や GUI を使わず、スクリプトから直接呼び出すこともできます。
最小構成は「園児 → 必要人員 → 求解」の 3 ステップです。

```python
from datetime import date, time
from shiftai.domain import AgeClass, ChildPlan, Contract, Role, StaffMember, build_slots
from shiftai import standards, solver
from shiftai.local_rules import get_standard

# 1) 基準を選ぶ
standard = get_standard("福岡市")

# 2) 対象日と時間帯を決める
day = date(2026, 10, 1)
days = [day]
slots = build_slots(time(9, 0), time(12, 0), 60)   # 9:00-12:00 を 60 分単位に

# 3) 園児 40 名（3 歳児、全員 9:00-12:00 在園）
children = [
    ChildPlan(
        child_id=f"C{i:03d}", name=f"園児{i}", day=day,
        arrive=time(9, 0), depart=time(12, 0),
        age_class=AgeClass.AGE_3,
    )
    for i in range(40)
]

# 4) 必要人員を算出（根拠つき）
requirements = standards.build_requirements(
    children, days, standard,
    day_open=time(9, 0), day_close=time(12, 0), granularity_min=60,
)

# 5) 職員 8 名（保育士、正職員 40 時間/週）を用意
staff = [
    StaffMember(
        staff_id=f"S{i:02d}", name=f"職員{i}",
        roles=(Role.HOIKUSHI,),
        contract=Contract(weekly_hours=40, daily_hours=8),
    )
    for i in range(1, 9)
]

# 6) 解を求める
result = solver.solve_shift(
    children, staff, requirements,
    time_limit_sec=15, standard=standard,
)
print("状態:", result.status.value)
for r in requirements.for_day(day):
    print(f"  {r.slot.label}  {r.age_class.value}: 在園{r.child_count}名 → 必要{r.needed_staff}名")
    print(f"    根拠: {r.basis}")
```

```console
状態: 最適解
  09:00-10:00  3歳児: 在園40名 → 必要5名
    根拠: 3歳児 40名 ÷ 8 = 5名（定員比8:1、切り上げ）／保育標準時間
  10:00-11:00  3歳児: 在園40名 → 必要5名
    根拠: 3歳児 40名 ÷ 8 = 5名（定員比8:1、切り上げ）／保育標準時間
  11:00-12:00  3歳児: 在園40名 → 必要5名
    根拠: 3歳児 40名 ÷ 8 = 5名（定員比8:1、切り上げ）／保育標準時間
```

この例では **40 名の 3 歳児に対し、3 時間帯で 5 名ずつ必要**と判定されました。
`最適解` と出ているのは、時間制限内に**最適性まで証明**できたからです。

> **Tip**: 最適化状態は `最適解` / `実行可能解` / `部分的なシフト` / `解なし` / `エラー` の 5 種類です。
> `最適解` でなければ `実行可能解` 以降です。`部分的なシフト` は貪欲法のフォールバックが働いた状態です。

## 5. 画面（Streamlit）の構成

GUI は 5 タブ構成です。各タブの実装は `src/shiftai/ui/` に対応します。

| タブ | 名前 | 実装ファイル | 役割 |
| --- | --- | --- | --- |
| 1 | データ投入 | `tab_data.py` | CSV / Excel / JSON のアップロード、サンプル・テンプレートの投入、**直接編集の Undo/Redo**、**入力チェック** |
| 2 | 必要人員 | `tab_requirements.py` | 配置基準と開所時間の選択、時間帯ごとの必要人員と**根拠**のヒートマップ表示 |
| 3 | シフト作成 | `tab_solve.py` | 事前の実現可能性チェック、自動実行、KPI、違反一覧、配置推移グラフ、**不足理由の診断と緩和モード**、**勤務パターンの整列報告** |
| 4 | シフト表・微調整 | `tab_shift.py` | 編集可能な勤務グリッド、手動固定セルの指定、曜日ピボット |
| 5 | 出力 | `tab_export.py` | 各種ファイルのプレビューとダウンロード、ICS/Excel/ZIP、GAS 書き戻し |

サイドバーには **7 つのパネル**（園情報・配置基準・**勤務パターン**・上書き・対象期間・目的関数・GAS 連携）があり、
入力を変えるたびにそれ以降のパイプが自動的に無効化されます。

### 5-a. データ投入タブの入力チェック（Undo/Redo）

タブ1 は表をそのまま編集でき、各表に「元に戻す」「やり直す」（最大 25 段）がある。
編集内容は入力チェックに即時反映され、**エラーがあれば「✅ この内容で読み込む」
は押せない**。主な指摘は次のとおり。

| 表 | エラーになる例 |
| --- | --- |
| 園児 | 降園時刻が登園時刻と同じか後／園児ID+登園日が重複／欠席がオンで理由が空 |
| 職員 | 職員IDが重複／週契約時間 0 以下／1日の契約時間が週を超える／最早始業が最遅終業以降 |
| 希望休 | 職員IDが職員表にない（読み込み時に捨てられる）／終了が開始と同じか前 |

警告（期間外の登園日、開所前の登園など）は読み込みを止めない。
詳細は [`docs/06_運用手引き.md`](docs/06_運用手引き.md) を参照。

### 5-b. 勤務パターンの整列（早番・日勤・遅番）

サイドバー「⏰ 勤務パターン（早番・日勤・遅番）」で有効にすると、
勤務ブロックの開始・終了をその枠へ引き寄せる。生成後に**整列率**と
早番・日勤・遅番・その他の日数が表示される。

**配置基準を破る差し替えは行わない**（据え置きの理由が 1  件ずつ表示される）。
既定は無効。`--patterns` / `--patterns auto` でも指定できる。

### 5-c. 解けないときの診断と緩和モード

タブ3 の「🔍 なぜ解けないのか（原因の特定と緩和モード）」:

- **不足表**: どの日のどの時間帯で何名が不足したか（必要人員 / 供給人員 / 不足人数）
- **区分**: 人員不足 / 保育士不足 / 総人時不足 / 配置可能人時 0。対応も提示
- **緩和モード**: L0 厳格 … L4 希望休・休園日を無視。緩めた制約は常に表示
- **緩和ラダー**: L0 から順に実測し、初めて解けた段階を報告（自動では走らない）
- **IIS**: 制約グループを 1 つずつ外して矛盾の当事者を絞り込む（自動では走らない）

1 日の上限時間（法定 10 時間）はどの段階でも緩めない。

## 9. 既知の制約と注意点

実際にサンプルデータで動かして分かった注意点を先に列挙します。

### `payroll.csv` の `実働時間` が 0.00 になることがある

サンプルの実行結果で、次のような行が出力されます。

```console
$ grep "^S19," out/payroll.csv
S19,三浦七海,子育て支援員,パート,4,3.5,6.0,0.0,0,1,0
```

`総勤務時間 3.5` / `総休憩時間 6.0` に対し、`実働時間` は `0.0` になっています。
`exporter.py` の `net_hours = max((worked_min - break_min) / 60.0, 0.0)` が
負値を 0 にクランプしているためです。

背景として、同じ実行では `SPLIT_SHIFT`（勤務が分断）や `BREAK_FRAGMENTED`（休憩が分断）
の要調整が大量に出ています。CBC が時間制限内で「勤務 1 セル・休憩 4 セル」のような
配分を出してしまうことがあり、このときの `HOURS_IMBALANCE` の要調整も
同時に出ています。休憩合計が勤務合計を上回るのは、この配分が非現実的なためです。

**運用上の注意**: `payroll.csv` の `実働時間` と `推定人件費` は、
勤務が分断された職員で過小評価になります。給与計算の確定値としては使わず、
`総勤務時間` と実際の勤務表で照合してください。
分断を抑えるペナルティの重み付けが実運用で十分かどうかは、
`docs/02_ソルバ仕様.md` の「認識している限界」節を参照してください。

### 目的関数値は金額でも人時でもない

`summary.md` の「目的関数値」（この例では `202,432.35`）は
内部のペナルティ重み付きコストです。**金額でも人時でもありません**。
重みプロファイルは `--standard` によって変わるため、値そのものを
異なる `--standard` の間で比較しないでください。
比較したいときは同じ `--standard` と十分な `--time-limit` で揃えます。

### CBC は決定的でない

同じ入力・同じ `--time-limit` でも、CBC の探索が時間制限のどこで止まるかによって
`実行可能解` になるか `部分的なシフト`（貪欲法フォールバック）になるかが変わることがあります。
再現したい場合はサンプルデータの `--seed` を固定し、
`最適解` が出るだけの十分な `--time-limit` を確保してください。
