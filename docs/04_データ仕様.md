## 1. 入力の全体像

### 1.1 3 つの表

| 表 | クラス定数 | 既定ファイル名 | 列数 | 省略すると error になる列 | 省略しても読み込める列 |
| --- | --- | --- | ---: | ---: | ---: |
| 園児（登降園予定） | `CHILDREN_COLUMNS` | `children.csv` | 12 | 5 | 7 |
| 職員 | `STAFF_COLUMNS` | `staff.csv` | 15 | 2 | 13 |
| 希望休・出勤不可 | `PREFERENCE_COLUMNS` | `preferences.csv` | 6 | 3 | 3 |

「省略すると error になる列」とは、**その列が空だと該当行がスキップされる**列のことである
（`LoadIssue.level == "error"`。`data_loader` に必須列の宣言リストは無く、
`load_children` / `load_staff` / `load_preferences` の行変換が順に値を読む）。
「省略しても読み込める列」は空文字または既定値で埋めて読み込みが継続する。
**列が 1 つもない（ヘッダが空）場合だけ、表全体がスキップされて空リストになる。**

**`preferences.csv` 自体は任意**（表自体が存在しなくてもよい）。
`shiftai template --out template` で各 1 行入りの空テンプレートを出力できる。

### 1.2 対応する形式

| 拡張子 | 処理 | 備考 |
| --- | --- | --- |
| `.csv` | `pandas.read_csv` | 文字コードは 3 つ依次に試す（後述） |
| `.xlsx` / `.xlsm` / `.xltx` / `.xltm` / `.xls` | `pandas.read_excel`（openpyxl） | `.xls` は openpyxl 非対応のため CSV に変換が必要 |
| `.json` | `json.loads` の後 DataFrame 化 | 3 形態に対応（後述） |
| 拡張子なし | 内容で判定 | 先頭が `{` または `[` なら JSON、それ以外は CSV |

**形式判定の順序**（`read_table`）:
1. `DataFrame` を渡されたらそのままコピー
2. 空バイト列なら空 DataFrame（列名は既定の列一覧）
3. バイト列が `PK\x03\x04`（xlsx のシグネチャ）または OLE2 形式、または拡張子が Excel の一覧にある → Excel として読む
4. 先頭が `{` または `[` → JSON として読む
5. それ以外 → CSV として読む

### 2.1 変換ルール

**年齢の変換**（`_parse_age_class`）:
- 数字のみ（`2`）→ `AgeClass.from_years(2)` = `2歳児`
- `0歳児` / `3歳` のような文字列 → 対応する `AgeClass`
- `5` / `5歳` / `5歳児` / `5歳児以上` / `6` / `6歳` → `AGE_5`（5 歳以上）
- それ以外 → `None`（`error` レベルの `LoadIssue` を作り、その行をスキップする）

**欠席の扱い**: `欠席=true` の場合、`登園時刻` と `降園時刻` は空でもよい
（`0:00` に置かれる）。`欠席=false` の場合は両方が必須。

**在園時間の検証**: `ChildPlan.__post_init__` で
「`降園時刻 <= 登園時刻` なら `ValueError: 在園時間が不正です: {園児ID} {登園}-{降園}`」。
欠席でない行でこの検証に失敗すると **error** になる（行はスキップされる）。

**重複の検証**: 同じ `(園児ID, 登園日)` の組が 2 回現れると **error**
（`重複しています（C001 / 2026-09-28 は 1 行目と重複）`）。

**短時間保育の扱い**: `is_short_time=True` の園児は保育標準時間帯の在園者数にだけ
計上される（`standards.count_children_by_slot`）。

## 2.5 園業務支援システム CSV の取込（`importers.py`）

CoDMON / キッズリー などで出力した園児 CSV を、本アプリ形式へ読み替えるアダプター。
タブ1「園児」の「🔗 園業務支援システムから取り込む」から使う。

### 2.5.1 プロファイル

| キー | 対象 | 主な列名の例 |
| --- | --- | --- |
| `codemon` | CoDMON | 園児コード / 園児氏名 / 利用日 / 登園予定時刻 / 降園予定時刻 |
| `kids_ryu` | キッズリー | 園児ID / 氏名 / 登園予定時刻 / 降園予定時刻 / 延長保育利用 |
| `generic` | 上記以外 | 園児ID / 氏名 / 登園日 / 登園時刻 / 降園時刻 |

列名は :func:`data_loader.normalize_header` と同じ規則（NFKC 正規化・記号除去）で照合する。
選択欄の既定値は `detect_profile(frame)` が列名の一致数で推定する。

### 2.5.2 変換の約束

* 出力は常に `data_loader.CHILDREN_COLUMNS` に揃えた DataFrame（そのまま `load_children` に渡せる）。
* 対応する列が無いものは空欄にし、`ConvertResult.missing` に列挙する。
* 和暦（`R8.9.28`）は西暦に変換する（`data_loader.parse_date` は和暦を受け付けないため）。
* 年齢は `0`〜`5` に丸め、月齢表記（`11ヶ月`）は 0 歳児にする。
* 短時間保育の列が無い場合だけ、保育標準時間帯と完全一致する行を推定する。
  「あり／なし」が明示されている列がある場合はその値を優先する。
* 欠席・早朝・延長のフラグは「あり／なし」表記も吸収する（`importers._flag`）。

### 3.1 契約時間の自動計算

```
週契約時間が 0 以下  ->  max(1日契約時間, 1.0) * 2.0   で計算し warning
1日契約時間が 0 以下  ->  max(週契約時間 / 5.0, 1.0)  で計算し warning
```

**実測**（週契約時間・1日契約時間が空の行）:
`週契約時間を既定値 2 にしました` / `1日契約時間を既定値 1 にしました`

**注意**: この既定値は極端に小さい。実際の職員データでは必ず明示すること。

### 3.2 `Contract` に設定されないその他の値

`data_loader` から `Contract` を作るときに次の項目は**設定されない**（`Contract` の既定値になる）:

| `Contract` のフィールド | 既定値 | 備考 |
| --- | --- | --- |
| `min_rest_hours` | 11.0 | 労働基準法第 9 条（休息時間 11 時間） |
| `granularity_min` | 30 | `Contract` 側では未使用（`RequirementTable` 側を使う） |
| `can_work_holiday` | True | 休日勤務可能。CSV からは変更できない |
| `overtime_allowed` | True | 残業許可。CSV からは変更できない |

`can_work_holiday=False` や `overtime_allowed=False` にしたい場合は、
`data_loader` を経由せず `Contract` を直接構築する必要がある。

| 列名 | 必須 | 型 | 値の形式 | 不正時の扱い |

### 4.1 種別のマッピング（`PREFERENCE_TYPES`）

| 入力 | 正規化後 | 扱い |
| --- | --- | --- |
| `希望休` / `希望` | `希望休` | **ハード制約**（不在時間帯） |
| `出勤不可` / `不可` | `出勤不可` | **ハード制約**（不在時間帯） |
| `出勤希望` / `出勤希望日` | `出勤希望` | ソフト制約（出勤すると `preference_match_bonus`） |
| `休み希望` / `希望休希望` | `休み希望` | ソフト制約（出勤すると `preference_miss_penalty`） |
| その他の文字列 | `希望休` | **warning** を出してハード制約として扱う |

**ハードとソフトの違い**（`load_preferences`）:

```python
hard_kinds = {"希望休", "出勤不可"}
if kind in hard_kinds:
    entry.unavailable.append(Unavailability(day=day, start=start, end=end, reason=reason or kind))
elif kind == "出勤希望":
    entry.preferred_days = frozenset(entry.preferred_days) | {day}
else:  # 休み希望
    entry.preferred_off_days = frozenset(entry.preferred_off_days) | {day}
```

**ハード制約の効き方**: `unavailable` に入るので `solver` の `_is_unavailable` で
`w` 変数が定数 0 になる。**出勤すると `gap_analysis` が `WORK_ON_UNAVAILABLE`（BLOCKER）を出す。**

**空欄の時間指定**: `開始` と `終了` が両方空なら終日（0:00〜23:59）として扱われる。
`終了 <= 開始` の場合も `23:59` に補正される。

### 4.2 職員CSVにいない職員ID

`load_bundle` の最後で、`preferences` にある職員IDが `staff` にいない場合:
`希望休のある職員 {職員ID} が職員CSVにいません` の **warning** が出る。
（エラーにはならない。`StaffPreferences` は作られるが無視される。）

### 4.3 `avoid_early` / `avoid_late` の無効化

`StaffPreferences.notes` に次の文字列が含まれると、対応するフラグが `True` になる:

| `notes` に含まれる文字列 | 設定されるフラグ |
| --- | --- |
| `早朝を避けたい` | `avoid_early = True` |
| `延長を避けたい` | `avoid_late = True` |

`sample_data` は `avoid_early` / `avoid_late` を設定するときにこの文字列を `notes` に付けている。
CSV から `StaffPreferences` を作る経路では、`notes` 列はこの文字列を含まないと
フラグが立たない（**CSV の `備考` 列は `StaffPreferences` に伝わらない**）。
そのため CLI からの CSV 経路では `avoid_early` / `avoid_late` は常に `False` になる。
UI から直接 `StaffPreferences` を作る場合は別途設定できる。

## 6. ヘッダ名のゆれ吸収

### 6.1 正規化（`normalize_header`）

```python
def normalize_header(name: Any) -> str:
    text = unicodedata.normalize("NFKC", str(name)).strip()
    return _NON_WORD.sub("", text).lower()
```

`_NON_WORD` は空白・全角空白・`_-()[]{}<>"'、。,./\\:：*#!$%&+=|~@\`^` を削除する。

**実測**:

| 入力 | 正規化結果 | 備考 |
| --- | --- | --- |
| `園児ＩＤ` | `園児id` | 全角英字を NFKC で半角化 → 小文字化 |
| ` 園児 ID ` | `園児id` | 空白を除去 |
| `職員ID（主）` | `職員id主` | **括弧が削除される** |
| `staff_id` | `staffid` | アンダースコアが削除される |
| `Staff Id` | `staffid` | |
| `1日契約時間` | `1日契約時間` | |
| `年齢（歳）` | `年齢歳` | |
| `*備考*` | `備考` | |
| `a_b-c` | `abc` | |
| `ＤＡＴＥ` | `date` | |

### 6.2 照合の 3 段階（`infer_columns`）

`{実際の列名: 期待列名}` の辞書を返す。3 段階で順に照合する。

1. **正規化した名前が `_CANONICAL` に完全一致し、かつ期待列に含まれる場合**
   （全角・空白・記号を無視した完全一致）
2. **`_COLUMN_ALIASES[期待列]` の別名に一致する場合**
   （正規化してから別名リストと比較。別名も正規化して照合する）
3. **前方一致または後方一致する場合**
   （`key.startswith(target)` または `target.startswith(key)`）

**重要な制約**: 同じ期待列に **2 回割り当てない**（`used` 集合で管理）。
最初の列が優先される。

**期待列が見つからない場合**: `_iter_rows` が
`[warning] 全体 {列名}: 列「{列名}」が見つかりません（空として扱います）` の `LoadIssue` を作る。

## 7. エラー処理方針

### 7.1 「1 行の不正で全体が落ちない」設計

`data_loader` の第一原則は **「1 行の不正で全体が落ちない」**こと。
`load_children` / `load_staff` / `load_preferences` は
`(値, issues)` のタプルを返し、`issues` に `LoadIssue` を積み上げる。
途中で `raise` することはなく、**不正な行だけをスキップして読み込みを続行する**。

### 7.2 `LoadIssue`（1 件の問題）

```python
@dataclass
class LoadIssue:
    level: str  # "error" または "warning"
    row: int  # 0 始まりの行番号。全体に対するものは -1
    column: str  # 問題があった列名
    message: str  # 日本語の説明
```

`__str__` の形式: `[{level}] 第{row+1}行 {column}: {message}`
（`row == -1` の場合は `第{row+1}行` ではなく `全体`）

### 7.3 `LoadResult`（読込結果のまとめ）

```python
@dataclass
class LoadResult:
    children: list[ChildPlan] = []
    staff: list[StaffMember] = []
    preferences: dict[str, StaffPreferences] = {}
    issues: list[LoadIssue] = []
```

| プロパティ | 意味 |
| --- | --- |
| `errors` | `level == "error"` の `LoadIssue` の一覧 |
| `warnings` | `level == "warning"` の `LoadIssue` の一覧 |
| `ok` | `errors` が空なら `True` |
| `summary()` | UI 表示用の日本語サマリ（先頭 20 件まで） |

### 7.4 具体的な扱い

| 状況 | レベル | 処理 |
| --- | --- | --- |
| 期待列が見つからない | warning | 空文字として扱う |
| 園児ID が空 | **error** | 行をスキップ |
| 園児ID が重複 | **error** | 行をスキップ |
| 職員ID が空 | **error** | 行をスキップ |
| 職員ID が重複 | **error** | 行をスキップ |
| 年齢・登園日・時刻を解釈不能 | **error** | 行をスキップ |
| 資格（主）を解釈不能 | **error** | 行をスキップ |
| 在園時間が不正（降園 <= 登園） | **error** | 行をスキップ |
| 日付を解釈不能（希望休） | **error** | 行をスキップ |
| 週契約時間・1日契約時間が 0 以下 | warning | 自動計算して続行 |
| 月間最大時間 < 月間最小時間 | warning | 入れ替えて続行 |
| 最遅終業 <= 最早始業 | warning | `23:59` にして続行 |
| 種別の文字列が未知 | warning | `希望休` として続行 |
| 希望休のある職員が職員CSVにいない | warning | そのまま（無視される） |
| ヘッダが空 | **error** | 表全体をスキップ（空リスト） |

### 7.5 `LoadResult.summary()` の実出力


## 8. 文字コードとヘッダの日本語

### 8.1 文字コード

`ENCODINGS = ("utf-8-sig", "utf-8", "cp932")` の順に試す（`data_loader._decode`）。

| 優先 | コード | 備考 |
| ---: | --- | --- |
| 1 | `utf-8-sig` | **推奨**。Excel で開いても文字化けしない（BOM 付き） |
| 2 | `utf-8` | BOM なしの UTF-8 |
| 3 | `cp932` | Shift-JIS。Windows の Excel で保存した CSV に多い |

3 つとも失敗した場合は `utf-8` の `errors="replace"` でデコードする
（文字化け文字 `U+FFFD` が含まれるが、処理は続く）。

**cp932 の実測**（`cp932` で保存した CSV を読む）:
`園児ID,氏名,年齢,登園日,登園時刻,降園時刻` を正しく読み取り、
`ChildPlan(child_id='C001', name='佐藤 さくら', day=date(2026,9,28), age_class=2歳児, arrive=8:30, depart=17:00)` を生成した。

**注意**: `cp932` は 3 つ目の候補なので、`utf-8-sig` のファイルは 1 つ目で成功する。
`cp932` のファイルで 1 文字でも UTF-8 として通ると、気づかないまま文字化けする可能性がある。
**CSV は必ず BOM 付き UTF-8（`utf-8-sig`）で保存することを強く推奨する。**

### 8.2 ヘッダの日本語

- 期待列名は**すべて日本語**（`園児ID` / `職員ID` / `短時間保育` など）
- `normalize_header` で全角英数字を半角化する（NFKC 正規化）ため、
  `園児ＩＤ` と `園児ID` は同一視される
- 半角カナと全角カナは**区別される**（NFKC では全角カナ → 半角カタカナに変換される）
- 記号（`_-()[]{}、。,./:：*#` など）は照合時に削除される
- 英語ヘッダ（`child_id` / `staff_id` など）も `_COLUMN_ALIASES` で認識される

### 8.3 JSON の 3 形態

`_dataframe_from_json` が以下に対応:

| JSON の形 | 例 | 結果 |
| --- | --- | --- |
| `{"data": [...]}` | `{"data": [{"園児ID": "C002", ...}]}` | `data` を DataFrame 化 |
| `[{...}, {...}]` | `[{"園児ID": "C002", ...}]` | リストをそのまま DataFrame 化 |
| `{"children": [{...}]}` | `{"children": [{...}]}` | `種別` 列を付けて結合 |
| `[["列1", "列2"], ["値1", "値2"]]` | 2 次元配列 | 1 行目をヘッダとして扱う |

**実測**:
- `{"data": [["園児ID","年齢"], ["C003", 3]]}` → 列 `['園児ID', '年齢']`、1 行
- `{"children": [{...}]}` → 列 `['種別', '園児ID', '年齢', '登園日', '登園時刻', '降園時刻']`、1 行
- `"{oops"` → `ValueError: JSON を解釈できません: Expecting property name enclosed in double quotes: line 1 column 2 (char 1)`

### 9.8 `shift.ics` の形式

`to_ics` は floating time（タイムゾーン指定なし）で書く。改行コードは **CRLF**。

**実測（先頭）**:
```
BEGIN:VCALENDAR
VERSION:2.0
PRODID:-//shiftai//shift//JP
CALSCALE:GREGORIAN
METHOD:PUBLISH
BEGIN:VEVENT
UID:S01-20260928-1200-1330@shiftai.local
DTSTAMP:20000101T000000
DTSTART:20260928T120000
DTEND:20260928T133000
SUMMARY:勤務: 山田花子 (9/28(月))
DESCRIPTION:職種: 保育士 作業時間: 90 分
```

| フィールド | 内容 |
| --- | --- |
| `UID` | `{職員ID}-{YYYYMMDD}-{HHMM}-{HHMM}@shiftai.local` |
| `DTSTAMP` | `20000101T000000`（固定値。再現性のため） |
| `DTSTART` / `DTEND` | 勤務ブロックの開始と終了（`YYYYMMDDTHHMMSS`） |
| `SUMMARY` | `勤務: {氏名} ({M/D(曜)})` |
| `DESCRIPTION` | `職種: {資格} 作業時間: {分数} 分` |
| `X-ALT-DESC` | `職種: {資格}|時間帯: {開始}〜{終了}|勤務分数: {分数}` |

**折り返し**: RFC 5545 の 75 octet 制限に従い、UTF-8 の文字境界で分割して
`\r\n `（CRLF + スペース）で継続する。

**イベント数**: 職員 1 人 1 勤務ブロック = 1 イベント。
勤務が分断されている場合（`SPLIT_SHIFT` 警告があるとき）は、1 人につき複数イベントになる。

```markdown
# シフトサマリー: あさひ保育園

- 総実働時間: 404.00 時間
- 推定人件費合計: **674,812** 円

## 検出された制約違反
（表）
## 職員別勤務時間
（表）
## メッセージ
（リスト）
```

**注意**: `配置基準の不足セル` と `法令違反（ブロッカー）` の数値は `_shortfall_info()` の

（`stats` に `shortfall_cells` があればそれを使う、無ければ `SHORTFALL` を含む

### 9.10 `shift.xlsx`（`--zip` 指定時のみ）

`export_bundle_zip` は 4 シートの `.xlsx` を ZIP に含める。

| シート名 | 内容 |
| --- | --- |
| `シフト` | `shift.csv` と同じ（`shift_to_dataframe`） |
| `職員別勤務` | `shift_matrix.csv` と同じ（`shift_matrices`） |
| `給与計算` | `payroll.csv` と同じ（`payroll_dataframe`） |
| `配置基準` | `requirements.csv` と同じ（`requirements_dataframe`） |

シート名は Excel の制約（31 文字以内、特殊文字 `[]:*?/\` 不可）を
`_safe_sheet_name` で自動調整する。重複時は `_2`, `_3` を付ける。

### 9.11 出力の文字コード

| ファイル | 形式 | BOM |
| --- | --- | :---: |
| CSV 群 | UTF-8 | **あり**（`utf-8-sig`） |
| `shift.ics` | UTF-8 | なし（CRLF 改行） |
| `summary.md` | UTF-8 | なし |
| `shift.xlsx` | ZIP 内の OOXML | 該当なし |

`_write_csv` は `df.to_csv(path, index=False, encoding="utf-8-sig")` を呼ぶ。
`to_csv_bytes` は `BOM` 定数（`BOM = "\ufeff"`）を使って手動で BOM を付ける。
Excel で開いて文字化けしないのは、この BOM があるため。

## 10. GAS 連携のシート構成

### 10.1 `gas/Code.gs` の `SHEETS` 定数

`gas/Code.gs:18` で定義されているシート名マップ:

```javascript
var SHEETS = {
  attendance: '登降園予定',
  staff: '職員',
  shift: 'シフト'
};
```

`gas/Code.gs:24` の `ACTIONS` 定数:

```javascript
var ACTIONS = ['ping', 'read', 'write', 'append'];
```

**初出の英字併記**: シート名マッピングは「論理名」（`attendance`）を
「実シート名」（`登降園予定`）に変換する。クライアント側は論理名だけを扱う。

### 10.2 `SHEET_ALIASES`（`gas_client.py:28`）

クライアント側の論理名から実シート名への対応。

| 論理名 | 実シート名 | 備考 |
| --- | --- | --- |
| `children` | `attendance` | 園児（登降園予定） |
| `attendance` | `attendance` | 同上（直接指定も可） |
| `staff` | `staff` | 職員 |
| `preferences` | `希望休` | **GAS 側の `SHEETS` に無い名前**。タブを追加しておけばそのまま使う |
| `shift` | `shift` | 出力したシフト |

**注意点**: `preferences` の実シート名は `希望休` で、これは `gas/Code.gs` の
`SHEETS` に登録されていない。`resolveSheet` は
「`SHEETS` にあればその名前、シートに同名タブがあればそれ、無ければ `sheet not found` エラー」
という順序で解決する。`希望休` タブを Google シートに追加しておけば
`preferences` も `attendance` と同じ経路で書き込める。

### 10.3 API の約束（`gas/Code.gs` 冒頭）

```
GET  /exec?action=ping|read&sheet=<name>&secret=<SECRET>
POST /exec   {action:write|append, sheet, columns, data, secret}
応答は常に {ok, action, rows, columns, data, updatedAt} 形式の JSON
```

### 10.4 環境変数

| 変数名 | 既定値 | 用途 |
| --- | --- | --- |
| `SHIFTAI_GAS_URL` | （空） | Web App の `/exec` URL。**未設定なら `GasConfig.from_env()` は `None` を返す** |
| `SHIFTAI_GAS_SHEET` | `attendance` | 既定のシート名（論理名） |
| `SHIFTAI_GAS_SECRET` | （空） | スクリプトプロパティ `SECRET` と一致させる |
| `SHIFTAI_GAS_TIMEOUT` | 10 | タイムアウト（秒） |

**設定されていない場合**: 例外は出ない。`gas_client.available()` / `is_configured()`
が `False` を返し、UI で連携セクションを出し分ける。

### 10.5 デプロイ手順

**完全な手順は [`../gas/README.md`](../gas/README.md) を参照。** 以下は概要。

1. Google シートを作り、タブ名を `登降園予定` / `職員` / `シフト` にする
2. シートの「拡張機能」から「Apps スクリプト」を開く
3. `gas/Code.gs` の内容をコピペする
4. スクリプトプロパティに `SPREADSHEET_ID` と `SECRET` を設定する
5. 「デプロイ」から「新しいデプロイ」「ウェブアプリ」で `/exec` を発行する
6. 発行された URL を `SHIFTAI_GAS_URL` に設定する

**`/dev` と `/exec` の違い**: 編集画面の URL は `/dev` だが非公開なのでクライアントから
叩けない。コードを変更したら**必ず「デプロイの更新」**を行う。

### 10.6 エラー処理

`gas_client` はすべての通信エラーを `GasError` に統一する。

| 例外 | 原因 |
| --- | --- |
| `GasConfigError` | `GasConfig.base_url` が空、または `mode` が `replace`/`append` 以外 |
| `GasError` | HTTP エラー、接続不能、タイムアウト、空応答、JSON 以外、`ok: false` |

UI は `GasError` を握ってエラー表示のみを行い、処理を継続する。
