## 1. 環境構築

### 1.1 必要なもの

| 項目 | 要件 | 備考 |
| --- | --- | --- |
| Python | **3.11 以上** | `pyproject.toml` の `requires-python` |
| メモリ | 4 GB 以上 | CBC は単一プロセスで動作する。本番規模（14,039 変数）のモデル構築に数 GB を使う |
| make | 任意 | Windows には無いのでコマンドを直接叩く |
| 動作検証環境 | Python 3.12.3 | `requirements.txt` のコメントに記載 |

### 1.2 インストール（推奨: make）

```bash
make install-dev
```

内部で次の 2 つを行う。

```bash
python3 -m venv .venv
.venv/bin/pip install -e .            # 実行時依存
.venv/bin/pip install -r requirements-dev.txt   # 開発・テスト用依存
```

以降のコマンドは `.venv/bin/python` を使う。
`make test PY=.venv/bin/python` のように `PY` を上書きするか、`.venv` を有効化する。

### 1.3 インストール（make を使わない場合）

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"
```

`pip install -e ".[dev]"` は `pyproject.toml` の `[project.optional-dependencies].dev` を
解決する。`requirements-dev.txt` を使う場合は次の通り。

```bash
pip install -e .
pip install -r requirements-dev.txt
```

### 1.4 依存関係

**実行時依存**（`pyproject.toml` の `[project].dependencies`）:

| パッケージ | バージョン指定 | 用途 |
| --- | --- | --- |
| `streamlit` | `>=1.63,<2` | Web UI |
| `pandas` | `>=3.0,<4` | 表計算と入出力 |
| `numpy` | `>=2.4` | 数値計算の下支え |
| `pulp` | `>=2.9,<3` | MILP モデリングと CBC 呼び出し |
| `openpyxl` | `>=3.1` | `.xlsx` の読み書き |

**開発・テスト用**（`[project.optional-dependencies].dev` と `requirements-dev.txt`）:

| パッケージ | バージョン指定 | 用途 |
| --- | --- | --- |
| `pytest` | `>=9,<10` | テストランナー |
| `pytest-cov` | `>=4,<8` | カバレッジ |
| `pytest-timeout` | `>=2,<3` | テストごとのタイムアウト |
| `pytest-xdist` | `>=3,<4` | 並列実行 |
| `ruff` | `>=0.16,<1` | 静的検査と整形 |

**検証環境の実測**（2026-10-01 / Python 3.13.15）:
`streamlit 1.64.0 / pandas 3.0.6 / numpy 2.5.3 / PuLP 2.9.0 / openpyxl 3.1.5 /
pytest 9.1.1 / pytest-cov 7.1.0 / pytest-timeout 2.4.0 / pytest-xdist 3.8.0 / ruff 0.16.9`

実行時依存の版数は `requirements.txt` の「検証環境の実測」が正。
パッケージを更新したら **両方を同時に書き換える**こと
（`tests/test_docs_claims.py::test_検証環境の記載がドキュメント間で一致する` が検出する）。

**`pulp` の下限が 2.9 である理由**（`requirements.txt` のコメント）:
3.x / 4.x は `LpVariable` の仕様が大きく変わり、`cat="Binary"` / `cat="Integer"` の指定が
壊れる。`solver.py` は `LpVariable(..., cat=...)` と `LpProblem(cat=LpMinimize)` に
直接依存しているため、3.x へ上げると解のデコードが全滅する。

**入れていないプラグイン**: `pytest-benchmark` / `pytest-mock` / `pytest-asyncio` は
`tests/` を実際に調べた結果使われていないため、意図的に入れていない。

### 1.5 Windows 固有の注意

`Makefile` のインデントは **タブ (TAB)** である。スペースで書くと
`make: *** missing separator` で落ちる。

Windows ネイティブ環境には `make` がない。次のいずれかで代用する。

- WSL / Git Bash で `wsl make help` または `make help`
- make を使わず各ターゲットに対応するコマンドを直接叩く

```
install      -> python -m venv .venv && .venv\Scripts\pip install -e .
test-fast    -> python -m pytest -m "not slow"
lint         -> python -m ruff check .
run          -> streamlit run streamlit_app.py
```

## 2. `Makefile` のターゲット

`make help` で一覧が表示される（`.DEFAULT_GOAL := help`）。

| ターゲット | 内容 | 対応するコマンド |
| --- | --- | --- |
| `install` | venv を作り、実行時依存を editable で入れる | `python3 -m venv $(VENV)` + `pip install -e .` |
| `install-dev` | `install` に加えて開発・テスト用依存を入れる | `pip install -r requirements-dev.txt` |
| `run` | Streamlit アプリを起動する | `streamlit run streamlit_app.py` |
| `presets` | 配置基準プリセット一覧を表示する | `shiftai presets` |
| `compliance` | 制度別の適合チェックを実行する | `shiftai compliance --regulation 認可外保育施設 --capacity 40` |
| `sample` | サンプル CSV を `sample/` に出力する | `shiftai sample --out sample` |
| `template` | 空テンプレート CSV を `template/` に出力する | `shiftai template --out template` |
| `solve` | サンプルデータで 1 週間分をヘッドレス実行する | `shiftai solve --sample --out out` |
| `test` | 全テストを走らせる（slow を含む） | `python -m pytest` |
| `test-fast` | 速いテストだけ走らせる | `python -m pytest -m "not slow"` |
| `test-slow` | slow マーカーの統合テストだけ走らせる | `python -m pytest -m slow` |
| `test-parallel` | 速いテストをコア数で並列実行する | `python -m pytest -m "not slow" -n auto` |
| `cov` | カバレッジ付きで全テストを走らせる | `python -m pytest --cov=shiftai --cov-report=term-missing` |
| `lint` | ruff で静的検査する | `python -m ruff check .` |
| `format` | ruff で整形し、自動修正可能な指摘も直す | `python -m ruff format .` + `ruff check --fix .` |
| `clean` | キャッシュとビルド成果物を削除する | 対象を先に表示する。**出力物（`out/` `sample/` `template/`）は残す** |
| `distclean` | `clean` に加えて生成物も削除する | `out/` `sample/` `template/` を削除 |
| `help` | ターゲット一覧を表示する（既定） | — |

**`clean` の安全装置**:
- `make clean` は `guard` ターゲットに依存しており、**削除対象を先に表示してから**
  確認する
- 削除するのはリポジトリ内の相対パスのみ。`.` `~` 絶対パスは削除対象に含めない
- `.streamlit/secrets.toml` は **絶対に消さない**（GAS の SECRET を浴びているため）
- `PRUNE_NAMES := .git .venv venv env` は走査で降りないディレクトリ

## 3. テスト

### 3.1 基本的な使い方

```bash
python -m pytest                    # 全テスト
python -m pytest -m "not slow"      # 速いテストだけ
python -m pytest -m slow            # slow だけ
python -m pytest tests/test_solver.py   # 単一ファイル
python -m pytest -k "coverage"      # テスト名で絞り込み
```

### 3.2 `pyproject.toml` の pytest 設定

```toml
[tool.pytest.ini_options]
pythonpath = ["src"]      # src レイアウトの import を解決
testpaths = ["tests"]     # テストの収集対象
addopts = "--timeout=600"   # 1 テスト 600 秒で打ち切り（`-q` は付けない）
markers = [
    "slow: 時間が長い統合テスト（-m 'not slow' で除外）",
]
filterwarnings = [
    "ignore::DeprecationWarning",
]
```

- `pythonpath = ["src"]` により、`pip install -e .` をしなくても `import shiftai` ができる
- `addopts` の `--timeout=600` は pytest-timeout 由来。
  CBC が応答しなくなったときにテストが永久に止まるのを防ぐ
- `tests/conftest.py` の `pytest_collection_modifyitems` は **CBC を起動するテストに
  `slow` を自動的に付ける**。テストが `solve_shift` を直接呼ぶか、CBC を使う
  フィクスチャ（`solved_day` / `solved_week` / `day_report`）を要求するかを AST で
  判定する。手動で `@pytest.mark.slow` を付け忘れても `make test-fast` は速さを保つ。
  検証は `tests/test_static_guards.py::test_slow未付与のCBCテストは存在しない` が行う。

### 3.3 slow マーカーの意味

| マーカー | 用途 | 付け方 |
| --- | --- | --- |
| `slow` | 実際の CBC を起動し、MILP を解く統合テスト | **自動**（`conftest.py` の `pytest_collection_modifyitems`）。CBC を直接呼ぶか CBC フィクスチャを要求するテストに付く |
| （なし） | 単体テスト。ソルバを起動しない | 既定。`make test-fast` は `-m "not slow"` で CBC を起動するテストだけを除外する |

**CBC を起動するテストの確認方法**:
```bash
python -m pytest --collect-only -q -m slow       # 対象になるテスト
python -m pytest --collect-only -q -m "not slow" # 実行されるテスト
```


**使い分けの基準**:
- **変更前に `test-fast` を通す**（数秒〜2 分）
- **`solver` / `standards` / `domain` を触った場合のみ `test-slow` を通す**（数分）
- **PR では両方を通す**

**実測値の求め方**:
```bash
python -m pytest -m "not slow"
```
実行時間はの環境 と同等のCPU負荷に左右される。環境

**注意**: 174.90 秒は他の作業と並行に動いていたときの値なので、
基準値として使うなら 1 人で再計測すること。テストを追加するたびに総数は増えるため、
**passed 件数は固定値ではない**（3.6 節の件数表と同時に更新すること）。

### 3.4 カバレッジ

```bash
make cov
# = python -m pytest --cov=shiftai --cov-report=term-missing
```

`pyproject.toml` の設定:

```toml
[tool.coverage.run]
branch = false
source = ["shiftai"]

[tool.coverage.report]
exclude_lines = [
    "pragma: no cover",
    "if TYPE_CHECKING:",
    "raise NotImplementedError",
]
```

- `branch = false` なので行カバレッジのみ
- `source = ["shiftai"]` で対象パッケージを固定

### 3.5 並列実行

```bash
make test-parallel
# = python -m pytest -m "not slow" -n auto
```

`pytest-xdist` が必要（`dev` 依存に入れている）。
**CBC は CPU を使う**ので、並列度を上げると各テストが遅くなる。
効果を測りたいときは `-n 2` のような小さい値で試す。

### 3.7 なぜ小さい職員プールを使うのか

**`small_staff` が 6 名（保育士 4 名 + 支援員 2 名）である理由**:

1. **CBC の実行時間が入力サイズにほぼ比例する**
   6 名 × 1 日 × 10 時間帯で変数 319 個・制約 294 本。
   実測 5.25 秒で `Optimal / Optimal Solution Found`（**最適解が求まる**）。
   28 名 × 6 開所日 × 25 時間帯では変数 14,039 個・制約 18,906 本となり
   （実測手順は [`docs/02_ソルバ仕様.md`](02_ソルバ仕様.md) §2.7）、
   `--time-limit 60` でも `Optimal / Solution Found`（**実行可能解止まり**）になる。

2. **最適解を検証できる**
   小さい規模では CBC が最適性を証明するため、
   「このモデルはこの最適値になる」という assert を書ける。
   本番規模では最適解が求まらないので、目的関数値の検証ができない。

3. **一回限りの高速化**
   `slow` は CBC を起動するテストだけに付くので、`make test-fast`
   （`-m "not slow"`）は MILP を起動せずに済む。
   対象は `python -m pytest --collect-only -q -m slow` で確認できる。
   `solved_day` / `solved_week` を `scope="session"` にしてあるのは、
   同じ解を複数のテストで共有し、CBC の起動回数を抑えているためである。

4. **前提条件の明確化**
   6 名 · 6 名の規模なら「人手が足りない」事例と「足りている」事例を
   それぞれ最小構成で作れる。

**規模を大きくしてテストする場合は** `week_inputs`（週間）か
`sample_data.make_staff`（28 名）を使う。実行時間が増えるので `slow` マーカーが付く（自動付与）。

## 4. Lint

### 4.1 基本的な使い方

```bash
make lint          # = python -m ruff check .
make format        # = python -m ruff format . && python -m ruff check --fix .
```

### 4.2 設定の読み方

`pyproject.toml`:

```toml
[tool.ruff]
line-length = 100
target-version = "py311"

[tool.ruff.lint]
select = ["E", "F", "I", "UP", "B"]
ignore = ["E501", "B008", "UP042"]
```

| 項目 | 値 | 意味 |
| --- | --- | --- |
| `line-length` | 100 | 1 行の最大文字数 |
| `target-version` | `py311` | 構文の自動判定の基準 |
| `select` | `E` | pycodestyle のエラー（whitespace など） |
| | `F` | Pyflakes（未使用の変数・import、定義順の誤り） |
| | `I` | isort（import の並び順） |
| | `UP` | pyupgrade（Python 3.11 向けの書き換え） |
| | `B` | flake8-bugbear（潜在的なバグ） |
| `ignore` | `E501` | 行が長すぎる指摘を**無効化**。整形は `ruff format` に任せる |
| | `B008` | 関数の既定引数での関数呼び出しを**許容**（`Field(default_factory=...)` で必要） |
| | `UP042` | `class X(str, Enum)` の `StrEnum` 化を**無効化** |

### 4.3 `UP042` を無効化している理由

`pyproject.toml` に理由コメントが付いている:

```toml
# UP042: `class X(str, Enum)` は `enum.StrEnum` へ移行しない。
# 本プロジェクトは `enum.value` をそのまま JSON/CSV に出力しており、
# StrEnum 化すると `str(Role.HOIKUSHI)` が "Role.HOIKUSHI" から "保育士" へ変わる等、
# 観測可能な挙動が変化するため意図的に無効化する。
```

**実測**: 修正前後で `str(Role.HOIKUSHI)` == `"Role.HOIKUSHI"` であることを確認済み。
`UP042` の自動修正を適用すると、JSON と CSV の出力経路の挙動が変わる。

**注意**: `pyproject.toml` を他の変更と同じタイミングで行う場合がある。
`UP042` の ignore 行を巻き戻さないこと。

### 4.4 よく使う ruff オプション

python -m ruff check src/shiftai/solver.py # 単一ファイル
python -m ruff check --fix .               # 自動修正可能なものを直す
python -m ruff check --output-format=concise .   # 1 行 1 件で出力

| コード | 意味 | 条件 |
| ---: | --- | --- |
| 0 | 正常終了 | BLOCKER なし、かつ `--strict` 未指定 or WARNING なし |

`shiftai solve --sample --time-limit 20` は終了コード **2**（BLOCKER 122 件）。

## 6. コード規約

### 6.1 実際のコードから読み取れる傾向

**docstring**:
- **すべての public 関数・クラスに docstring を書いている**
- 1 行の要約 + `:param ...:` / `:returns:` のセクション
- 日本語で書く（識別子は英語）

```python
def build_requirements(
    children: Sequence[ChildPlan],
    days: Sequence[date],
    standard: StaffingStandard,
    *,
    day_open: time,
    day_close: time,
    granularity_min: int = 30,
    enforce_min_two: bool = True,
) -> RequirementTable:
    """在園児データと配置基準から時間帯ごとの必要人員を算出する。

    :param children: 園児の登降園予定
    :param days: 対象日
    :param standard: 適用する配置基準
    :param day_open: 園の開所時刻
    :param day_close: 園の閉所時刻
    :param granularity_min: 時間帯の粒度（分）
    :param enforce_min_two: 2名ルールを適用するかどうか
    :returns: 時間帯ごとの必要人員
    """
```

**識別子**:
- 関数・変数は **snake_case の英語**
- 型は **CamelCase の英語**
- 定数は **UPPER_SNAKE_CASE**（`SHIFT_COLUMNS` / `ENCODINGS` / `COST_COEFFICIENT`）
- モジュール内の定数は先頭にアンダースコアを付ける（`_DISCLAIM` / `_MIN_TWO_TEXT`）
- 実際のデータ文字列（列名・メッセージ・コード値）は**日本語**

**型注釈**:
- `from __future__ import annotations` で先頭に入れて遅延評価にしている
- `Sequence[T]` / `Mapping[K, V]` を使う（`list[T]` / `dict[K, V]` ではない）
  - 呼び出し側が `list` でも `tuple` でも渡せるようにするため
- `str | None` を使う（`Optional[str]` ではない）

**データクラス**:
- すべて `@dataclass(frozen=True)`（`SolveResult` など一部は `frozen=False`）
- 変更不可能にするのは、層をまたいで渡すときに「誰かが勝手に書き換えない」ことを保証するため
- フィールドのデフォルト値は `field(default_factory=...)` を使う

**列挙型**:
- `class Role(str, Enum)` のように **`str` を継承**する（JSON / CSV への出力を簡単にするため）
- `UP042` を無効化している理由は 4.3 節を参照

**コメント**:
- 日本語で書く
- 「**なぜ**」を書く。「**何**」はコードを読めば分かる
- 例:

```python
#  CBC の途中値（0.19 や 0.83 のような実数）を丸めてハード制約を満たすなら
# 正しい MILP 解なので採用する。満たさないなら解なしとして退避する。
```

**分岐**:
- 早期 return を好む（ネストを深くしない）
- 例外は `ValueError` を使う（`RuntimeError` は使わない）

**遅延 import**:
- 循環参照を避けるために必要最小限だけ使う
- 関数内でのみ import して、その理由をコメントで残す

### 6.2 変更するときの方針

1. **`domain.py` を変更する場合は型を先に追加する**
   既存フィールドの削除・型変更は破壊的変更。全モジュールに影響するので
   手順は [`01_アーキテクチャ.md`](01_アーキテクチャ.md) 6 節を参照

2. **公開 API を変えたら `tests/` を足す**
   新しい分岐には必ずテストを付ける

3. **CBC を起動するテストの `slow` は `tests/conftest.py` が自動付与する**（手動で付けない）
   付け忘れると `test-fast` が遅くなる

4. **新しいエラーコードを追加したら 3 箇所に反映する**
   - `gap_analysis.VIOLATION_CODE_LABELS` に日本語の説明を追加
   - `gap_analysis.check_violations` で判定ロジックを追加
   - `tests/test_gap_analysis.py` にテストを追加

5. **`make lint` と `make test-fast` を通してからコミットする**

## 7. トラブルシューティング

### 7.1 よくある問題

| 症状 | 原因 | 対処 |
| --- | --- | --- |
| `make: *** missing separator` | `Makefile` をスペースでインデントした | タブでインデントし直す |
| `ModuleNotFoundError: No module named 'shiftai'` | `pip install -e .` をしていない | `pip install -e ".[dev]"` または `pythonpath` 設定を確認 |
| `ImportError: cannot import name ...` | 循環参照が起きている | 遅延 import を使う。`domain` に依存を移動する |
| テストが実行ごとに落ちる | CBC の並列実行による競合、または `solver.py` の変更途中 | 該当テストに `slow` が自動付与されているか確認し、`-k` で単独実行して `stats["solver_status_pass1"]` を読む |
| CBC が応答しない | 時間が長すぎる入力 | `--time-limit` を小さくする。粒度を 60 分に下げる |
| Streamlit が起動しない | ポート衝突 | `--server.port 8502` を付ける |
| `.venv` が見つからない | venv を作っていない | `make install-dev` を実行する |

### 7.2 テストのタイムアウト

```bash
# 1 テストだけ 30 秒で打ち切る
python -m pytest tests/test_solver.py -k "slow_test" --timeout=30

# タイムアウトを無効にする
python -m pytest --timeout=0
```

`addopts` の `--timeout=600` が既定値。テストごとの `@pytest.mark.timeout(300)` で上書きできる。
