## 0. 免責と限界（先に読む）

> **本ツールの出力は、園長の責任での最終確認が前提である。**
> 本ツールは「シフトのたたき台」を作る道具にすぎない。
> 配置基準を満たしたかどうかの最終判断は、人が行う。

### 0.1 本ツールが行わないこと

1. **法令の遵守を保証しない**
   自治体ごとに配置基準が異なり、基準は改定される。本ツールのプリセットは
   「一般的な実務水準に基づく目安」であり、自治体の告示・条例・要綱・運用と
   一致する保証はない（`local_rules.py` の `_DISCLAIM`）。

2. **職員的个人な事情を把握しない**
   体調不良、家庭の事情、急な用事、早退希望。これらは `希望休`（出勤不可）として
   登録しなければ把握しない。

3. **最も合理的なシフトを保証しない**
   本番規模（職員 28 名 × 6 日 × 25 時間帯）では CBC が最適性の証明に至らず、
   「実行可能解」（制約を満たした解の一つ）しか得られない。
   小さい規模でも最適解は「基準を満たした中で一つの解」であり、
   事務的に最も合理的な配分とは限らない。

4. **保育室の区別を認識しない**
   `RequirementTable` は「日 × 時間帯 × 年齢クラス」であり、保育室ごとの定員・資格要件は
   区別しない。複数保育室で基準が異なる園は手動調整で補う必要がある。

5. **運用上の例外を代弁しない**
   法令・契約に反するシフトは制約として生成されないが、
   実際にはやむを得ない例外がある。**その例外を許すのは園長のみである。**

### 0.2 免責の位置づけ

本ツールの出力（`summary.md` / `violations.csv` など）には、
自治体の基準と一致する保証がないことを示す文言が付加される。
集計的な数値も目安であることを職員にも伝えること。

## 1. 日次の業務フロー

### 1.1 全体像

```
[1] 園から予定を受け取る          （前日まで）
        |
[2] データに投入する              （当日朝）
        |  園児CSV / 職員CSV / 希望休CSV
        v
[3] 必要人員を確認する            （当日朝）
        |  タブ2 / requirements.csv
        v
[4] シフトを自動作成する          （当日朝）
        |  タブ3 / shiftai solve
        v
[5] 微調整する                    （当日朝）
        |  タブ4 / shift_matrix.csv
        v
[6] 出力する                      （当日朝）
        |  タブ5 / bundle.zip
        v
[7] 職員へ配布する                （当日朝）
        |  紙 / カレンダー
        v
[8] 実行後に確認する              （当日夕方）
           実際の出勤状況との差分
```

### 1.2 各ステップの詳細

#### [1] 園から予定を受け取る

**期限**: 原則、前日まで。朝の同時対応は避ける。

**受け取るもの**:

| 情報 | 入手元 | 反映先 |
| --- | --- | --- |
| 園児の登降園予定 | 保護者からの連絡帳やアプリ | 園児CSV の「登園日」「登園時刻」「降園時刻」 |
| 延長保育・早朝保育の利用 | 保護者からの連絡 | 園児CSV の「早朝保育」「延長保育」 |
| 欠席の連絡 | 保護者からの連絡 | 園児CSV の「欠席」「欠席理由」 |
| 新入園児の追加 | 園の入園手続き | 園児CSV に追加行 |
| 退職・異動 | 人事 | 職員CSV から削除・変更 |
| 職員個人の希望休 | 職員本人 | 希望休CSV に追加行 |

**注意点**:

- **「延長保育を利用するか」が最も影響が大きい。** 園児 1 人が延長保育を利用すると
  必要人員が 1 名以上増える。需要が突発的に増えるため、前日中の把握が必須である。
- 延長保育の開始・終了時刻は園ごとに異なる。園の運用に合わせて
  `--open` / `--close` を設定し直す。
- 「今日は早退」「延長保育は利用しない」といった連絡が前日中に届くとは限らない。
  届いた日が遅いと、必要人員を 1 人分超過した状態でのシフト作成になる。

#### [2] データに投入する

**方法 3 つ**:

| 方法 | 対象 | 手順 |
| --- | --- | --- |
| 画面 | 日常運用 | タブ1「データ投入」で 3 つのファイルをアップロード |
| CLI | 定期運用 | `shiftai solve --children c.csv --staff s.csv --preferences p.csv --out out` |
| GAS | 複数園 | 園の Google シートから直接取得（[`../gas/README.md`](../gas/README.md) 参照） |

**投入後の確認**: `LoadResult.summary()` の**エラー件数が 0** であることを必ず確認する。

```
読み込み: 園児 34 名 / 職員 28 名 / 希望休 12 名 （エラー 0 件・警告 0 件）
```

**エラーが 1 件でもあれば投入をやり直す**（該当行だけがスキップされている）。
警告（列が見つからない、契約時間が自動計算された）は**内容を必ず読む**。

#### [3] 必要人員を確認する

**方法**: タブ2「必要人員」または `requirements.csv`

**確認する 3 点**:

1. **総必要人時**が職員の契約時間の合計を上回っていないか
2. **ピーク時の必要人員**が、勤務可能な職員数を超えないか
3. **対象日に休園日や行事が含まれていないか**

**実例**（`shiftai solve --sample --out out --time-limit 60` の出力 1 行目）:

```
必要人員: 6 日 / 25 時間帯 / 507.5 人時（ピーク 9 名）
```

この 507.5 人時に対し、職員の契約時間合計が 841.0 人時なら充足可能である。
**職員数や契約時間には余裕がある**ことを意味する。

必要人時が契約時間合計を上回る場合、シフトは組めない。3.1 節を参照。

#### [4] シフトを自動作成する

**方法**: タブ3「シフト作成」または CLI

```bash
shiftai solve --children c.csv --staff s.csv --preferences p.csv --out out --time-limit 60
```

**推奨する `--time-limit`**: **60 秒以上**。

実測（園児 34 名 × 6 日、職員 28 名、全国基準）:

| `--time-limit` | 結果 | 配置カバー率 | 法令違反（ブロッカー） |
| ---: | --- | ---: | ---: |
| 20 秒（2026-09-28 測定） | 貪欲法フォールバック | 82.3% | 126 件 |
| 20 秒（2026-09-29 再測定） | 貪欲法フォールバック | 84.5% | 122 件 |
| 60 秒（2026-09-28 測定） | 実行可能解 | **100.0%** | **0 件** |
| 60 秒（2026-09-29 再測定） | 貪欲法フォールバック | 84.5% | 122 件 |
| 120 秒（2026-09-28 測定） | 実行可能解 | 100.0% | 0 件 |

**実運用では 60 秒以上を指定する**。時間制限が短いと 1 パス目が
実行可能解を返せずに貪欲法へ落ち、BLOCKER（法令違反）が 100 件以上残る。

**運用者は必ず自分の環境で 1 回走らせて数値を確認する**。
上の表は特定の日付・特定のマシンでの測定値であり、**`--time-limit 60` で
100% になることを保証するものではない**。判断すべきは
「`summary.md` の配置カバー率が 100% か」「`violations.csv` の『法令違反』が 0 件か」
という 2 点だけであり、上の表の数値そのものを前提にしてはならない。

画面の場合: タブ3 の「シフトを自動作成する」ボタンを押す。実行中に進捗が表示される。

#### [5] 微調整する

**方法**: タブ4「シフト表・微調整」

**必ず目視確認する項目**:

| 項目 | 確認方法 | 問題があれば |
| --- | --- | --- |
| 配置基準の不足 | `gap.csv` の「不足」「不足保育士数」列が 0 か | 職員を追加するか、園児数を再確認 |
| 法令違反 | `violations.csv` の「区分」が「法令違反」の行 | 該当職員を配置し直す |
| 勤務時間の偏り | `payroll.csv` の「総勤務時間」列 | 最大と最小の差が大きい場合は手動で調整 |
| 休憩の連続性 | `shift_matrix.csv` の休憩セル | 休憩が分断されている場合は手動で結合 |
| 早朝・延長の偏り | `payroll.csv` の「早朝回数」「延長回数」 | 特定の職員に偏っている場合は配置を入れ替える |
| 個人の希望 | `preferences` との突き合わせ | 崩れた希望があれば UI で固定 |

**手動で固定する方法**: タブ4 でセルをクリックして状態を指定する
（「勤務」「休憩」「オフ」の 3 択）。固定したセルは再最適化时被る。

**再最適化の注意**: 固定セルがある場合、固定を保ったまま他のセルだけが再計算される。
固定を解除するには同じセルを再度クリックする。

#### [6] 出力する

**方法**: タブ5「出力」または CLI

```bash
shiftai solve ... --out out --zip
```

**出力ファイルと配布対象**:

| ファイル | 内容 | 配布対象 |
| --- | --- | --- |
| `shift_matrix.csv` | 勤務表（マトリクス形式） | 全職員（掲示用） |
| `shift.ics` | カレンダー形式 | 全職員（各自の予定として） |
| `shift.csv` | 職員ごとの勤務明細（長い形式） | 管理者（勤務管理用） |
| `payroll.csv` | 勤務集計と人件費 | 事務（給与計算用） |
| `requirements.csv` | 必要人員と算出根拠 | 保育主任（基準確認用） |
| `gap.csv` / `gap_daily.csv` | 過不足 | 保育主任（確認用） |
| `violations.csv` | 法令違反と要調整の一覧 | 保育主任（確認用） |
| `summary.md` | サマリー | 管理者（報告用） |
| `bundle.zip` | 上記すべてと `shift.xlsx` | 管理者（保存用） |

#### [7] 職員へ配布する

| 方法 | 対象 | 手順 |
| --- | --- | --- |
| 紙（印刷） | 掲示用 | `shift_matrix.csv` を A3 横で印刷して掲示 |
| カレンダー | 各自の予定 | `shift.ics` を Google カレンダーに取り込む |
| 個別連絡 | 個別に把握 | `shift.csv` を参照して 1 人ずつ連絡 |

**配布前に必ず読むこと**:

- `summary.md` の「配置基準の不足セル」が **0 件**であること
- `violations.csv` の「法令違反」が **0 件**であること
- `violations.csv` の「要調整」を全て読んだこと

`shift.ics` のイベントは floating time（タイムゾーン指定なし）で書かれるため、
各端末のタイムゾーンに依存しない。ただし夏時間などの時間帯変動がある環境では
注意が必要である。

#### [8] 実行後に確認する

**当日夕方に確認する 3 点**:

1. 実際の出勤状況が予定と一致しているか
2. 急欠が発生したときの代替対応は取れたか
3. 翌日に持ち越すべき事項（未充足の希望、勤務時間の偏り）はあるか

**急欠が出たときの対応**:

1. 職員に連絡して、変更可能か確認する
2. `preferences.csv` に「出勤不可」の行を追加する
3. `shiftai solve` を再実行する
4. 出力し直して配布し直す

## 2. 運用ルール

### 2.1 「法令違反が残ったシフトを配らない」

**これが本ツール運用の最上位ルールである。**

#### ルールの内容

`violations.csv` の「区分」列に **「法令違反」** が 1 件でもあれば、
そのシフトを職員に配布してはならない。

#### なぜそうなのか

| 理由 | 説明 |
| --- | --- |
| **法令違反は「やむを得ない」で免責されない** | 保育所の職員配置基準は児童福祉法に基づく基準であり、満たさない場合は行政処分や指定削除につながる |
| **保育の質に直結する** | 配置基準を下回る状態では、発達支援や安全確保に必要な人員が足りない |
| **子どもの安全に関わる** | 保育は人員配分であり、基準を下回ると事故が起きるリスクが上がる |
| **園の社会的信用に関わる** | 行政指導の記録が残る |
| **職員の健康に関わる** | 1 日の勤務が 8 時間 45 分を超えた場合（`STATUTORY_DAILY_HOURS`）は労働基準法違反である |

#### 実運用の手順

```
[1] violations.csv を開く
[2] 「区分」列が「法令違反」の行を数える
[3] 0 件なら次へ進む
[4] 1 件以上なら:
    a) 該当行の「内容」列を読む
    b) その時間帯の必要職員数と配置数を確認する
    c) 職員を追加する／園児数を再確認する／開所時間を見直す
    d) shiftai solve を再実行する
    e) 違反 0 件になるまで繰り返す
[5] 違反 0 件になったことを確認してから配布する
```

#### 違反コードごとの対処

| コード | 意味 | 対処 |
| --- | --- | --- |
| `SHORTFALL_STAFF` | 必要人員に足りない | 職員を追加するか、園児数を再確認 |
| `SHORTFALL_QUALIFIED` | 必要保育士数に足りない | 保育士を追加するか、支援員に代替できるか確認 |
| `WORK_ON_UNAVAILABLE` | 希望休に配置されている | 再最適化する（固定セルを解除してから） |
| `WORK_ON_CLOSED_DAY` | 休園日に勤務している | 再最適化する（休園日の設定を確認） |

#### 例外を認めるのは園長のみ

やむを得ない事由（職員の急病、当日の欠員など）で配置基準を下回る必要がある場合、
**園長が判断**してその旨を記録した上で例外的に配布することができる。
ただしこれは**本ツールの自動チェックを無視する**ことであり、
**記録と責任は園長にある**。

### 2.2 早朝保育の運用

#### 早朝保育とは

開所時刻（既定 7:15）から保育標準時間の開始（8:30）までの時間帯。
園児が早朝保育を利用する場合のみ必要人員が発生する。

#### 運用のポイント

1. **需要を事前に把握する**
   園児CSV の「早朝保育」列を `true` にすると、必要人員に反映される

2. **早朝の配置基準を確認する**
   延長保育ほど代替措置が広いとは限らない。自治体の基準に依存するため、
   該当する自治体の基準で代替措置が認められるかを確認する

3. **早朝の希望を確認する**
   `avoid_early`（早朝を避けたい職員）は `early_shift_penalty`（既定 2.0）で
   ペナルティが掛かる。`StaffPreferences` で設定する

4. **早朝保育の回数を記録する**
   `payroll.csv` の「早朝回数」列で確認する。特定の職員に集中していないか確認

5. **早朝保育が日常的に 2 名以上必要な場合**
   保育標準時間の前後に分けた運用（別室で受け入れる）を検討する

#### 実運用の注意

- 早朝保育の職員は**始業が早く、終業も早い**。家庭の事情（送迎、通園）に配慮する
- 早朝保育の職員には**始業前の準備時間**を確保する
- 早朝保育の回数と時間を把握した上で、**勤務の偏りがないか**を `payroll.csv` で確認する

### 2.3 延長保育の運用

#### 延長保育とは

保育標準時間の終了（17:15）から閉所時刻（既定 19:30）までの時間帯。

#### 運用のポイント

1. **延長の利用は突発的に増える**
   保護者からの連絡が当日夕方に来ることがある。
   翌日の朝の配置に備えて、早めに把握しておく

2. **延長では代替措置が自治体の基準で異なる**
   延長保育では「保育士 1 名に他資格者を 1 名加えて代替」できる自治体がある。
   `local_rules.list_presets()` の `late_care_relaxed` を確認する

3. **代替措置の期限を確認する**

   | 期限 | 自治体 |
   | --- | --- |
   | 18:30 まで代替可 | 東京都、大阪市、福岡市、神戸市、川崎市、京都市 |
   | 19:00 まで代替可 | 横浜市、名古屋市 |
   | 代替不可（保育士のみ） | 全国基準（厚労省）、札幌市、保育標準時間のみ園 |

   **それ以降の時間帯は保育士のみが必要**である。

4. **延長の労働時間を確認する**
   延長保育の職員は 1 日の勤務時間が長くなる傾向がある。
   `DAILY_HOURS_EXCEEDED`（契約上限超え）と
   `STATUTORY_DAILY_HOURS`（法定上限超え）を必ず確認する

5. **閉所時刻の設定**
   `--close` を 19:30 より後にすると必要人員が増える。園の実際の運用に合わせて設定する

#### 実運用の注意

- 18:30 以降の延長には保育士が必要である。この時間帯の配置を計画する
- 延長保育の職員は**終業が遅い**。翌日の始業が早すぎないか確認する
- **法定の 1 日 8 時間 45 分**を超える延長は `STATUTORY_DAILY_HOURS` として警告される。
  これを無視しない

### 2.4 連続勤務日数の管理

#### 連続勤務とは

同じ日に出勤し続けること。本ツールは `Contract.max_consecutive_days`
（CSV の「最大連続勤務日数」列、既定 5 日）に対して**ソフト制約**を設ける。

#### 管理の方法

1. **`max_consecutive_days` を正しく設定する**
   CSV の「最大連続勤務日数」列に契約上の値を書く
   （正職員 5 日、パート 3 日など）

2. **`CONSECUTIVE_DAYS` 警告を確認する**
   `violations.csv` に `CONSECUTIVE_DAYS` があれば、
   その職員は連続出勤日数を超えている。手動で調整する

3. **週の勤務日数も確認する**
   `WEEKLY_DAYS_EXCEEDED`（契約の週所定労働日数超え）も同時に出る

4. **職員の休日を確保する**
   連続勤務日数と週の勤務日数を合わせて、
   職員が十分な休日を確保できているかを `payroll.csv` の「勤務日数」列で確認する

#### 注意

連続勤務日数は**ソフト制約**なので、`CONSECUTIVE_DAYS` 警告が出ても
シフトは生成される。運用者が判断して調整する必要がある。
法令・契約の違反ではないため `BLOCKER`（法令違反）ではないが、
**職員の健康に直結する**ので強く調整を推奨する。

## 3. 前提条件の確認

### 3.1 職員数と契約時間が需要に対して足りているか

**これがシフトを組む前に必ず確認すべき最重要の前提である。**

#### 確認方法

**必要人時**と**契約時間の合計**を比較する。

```bash
# 必要人時とピーク時の必要人員を確認する
shiftai solve --sample --out out --time-limit 60
# 出力の 1 行目がこれ:
# 必要人員: 6 日 / 25 時間帯 / 507.5 人時（ピーク 9 名）
```

または `requirements.csv` を表計算ソフトで開き、「必要人員」列の合計を取る。

職員側の契約時間合計は `staff.csv` の「週契約時間」列の合計に
対象日数を掛けて概算する。

**実測（サンプルデータ、6 日分）**:

| 項目 | 値 |
| --- | ---: |
| 必要人時 | 507.5 人時 |
| ピーク時必要人員 | 9 名 |
| 職員の契約時間合計 | 841.0 人時 |
| 充足率 | 約 60% |

**充足率が低い場合**: シフトは組めるが余裕がない。欠員時に即座に対応できない。

**充足率が 100% を超える場合**: 構造的にシフトが組めない。
**職員数の増員、登降園時間の調整、延長保育の縮小**を検討する。

#### 充足率が低いときの確認事項

1. **適用している配置基準の値が正しいか**
   `shiftai presets` で自治体の基準が選ばれているか確認する

2. **園児数が多くはないか**
   保護者からの確認漏れで園児数が多くなっていないか

3. **延長保育の利用者が多すぎないか**
   延長保育の利用者は必要人員を押し上げる

4. **不要な開所時間が入っていないか**
   `--open` / `--close` の設定が園の運用と合っているか

#### 不足している場合のメッセージ

`solver` は人員不足を検出したとき、`SolveResult.messages` に「人員の見直し」節を出す。

実測（供給が需要に追いつかない場合）:

```
【人員の見直し】
  必要人員合計 9.0 人時／計画期間内の契約上限合計 16.2 人時（充足率 55% 相当）
  保有: 保育士 1 名（正職員 0 名・パート 1 名）／子育て支援員 1 名／その他 0 名
  ・2026-09-28 09:00-09:30 は人員そのものが足りません（3名必要/最大2名配置可能）。
    職員数の増員、登降園時間の調整、延長保育の縮小をご検討ください。
```

このメッセージが出たら、**シフト作成の手順を止めて**、人員の検討に入る。

### 3.2 職員構成の確認

**必要人時が足りていても、資格構成に問題があることがある。**

| 確認項目 | 内容 |
| --- | --- |
| 保育士の人数 | 必要保育士数（`needed_qualified`）を満たすか |
| 支援員の人数 | 延長保育の代替措置只能用か |
| 資格の偏在 | 1 人の保育士に勤務が偏っていないか |
| 勤務可能時間帯 | 全員が保育標準時間に勤務可能か |

**例**: 必要保育士数が 9 名だが保育士の契約時間が短い（パート中心）場合、
1 日に 9 名配置できるかどうかは、総時間には余裕があっても個別に確認する必要がある。
この場合、`payroll.csv` の「資格」列と「総勤務時間」列を職員ごとに確認し、
実際に 1 日 9 名配置できる状態かを判断する。

## 4. 複数保育室への対応状況と限界

### 4.1 現状

**本ツールは保育室を区別しない。**

`RequirementTable` の構造:

```
RequirementTable
  rows: { date: [Requirement, ...] }
  Requirement(day, slot, age_class, child_count,
              needed_staff, needed_qualified, slot_kind, basis, is_binding)
```

`Requirement` の識別に使われるのは「日付」「時間帯」「年齢クラス」であり、
**保育室は含まれない**。

### 4.2 影響

| 状況 | 影響 |
| --- | --- |
| 全保育室が同じ定員比の園 | 影響なし。年齢クラスごとにまとめて計算してよい |
| 保育室ごとに定員比が異なる園 | 影響あり。全体の基準で計算され、個別の差が反映されない |
| 保育室ごとに在園児数が異なる園 | 影響あり。全部屋分を合算してしまう |
| 小規模保育室がある園 | 影響あり。0 歳児がいない室は在園児数 0 として扱われる |
| 異年齢保育室がある園 | 影響あり。在園児を保育室ごとに分離できない |

### 4.3 回避策

#### 案 1: 手動で調整する（推奨）

1. 本ツールで全体のシフトを作る
2. `shift_matrix.csv` を確認し、保育室ごとに要調整箇所を特定する
3. タブ4「シフト表・微調整」で配置を手動で変更する
4. 保育室ごとの配置基準を満たしているかを**園長が確認**する

**この案が最も現実的である。** 本ツールの第一義は
「配置基準全体の充足」であり、保育室ごとの配分は運用者の判断に委ねられている。

#### 案 2: 園ごとに `build_standard` の `overrides` を使う

最も厳しい保育室の基準に合わせる。

```python
from shiftai import local_rules
from shiftai.domain import AgeClass

std = local_rules.build_standard("全国基準（厚労省）", overrides={
    "ratios": {AgeClass.INFANT: 2.5},   # 最も厳しい保育室の基準に合わせる
})
```

**この案は「必要人員を過大に見積もる」ことになる**ため、人員計画には影響する。
運営方針に応じて選ぶ。

#### 案 3: 保育室ごとの必要人員を別々に計算する（将来要望）

現状は未実装。`Requirement` に `room` フィールドを追加し、
`solver` の配置制約を保育室ごとに追加する方針になる。
**大幅な改修が必要**であり、簡単には対応できない。

### 4.4 0 歳児がいない保育室がある園

0 歳児がいない保育室（小規模保育室や異年齢保育室）は、
本ツールでは 0 歳児の在園児数 0 として扱われる。
このため、0 歳児の保育室が必要とする最低 2 名（2 名ルール）が**計算されない**。

**運用上の対処**:

- 小規模保育室の配置基準は**園長が別途管理**する
- 本ツールのシフトと照合せたとき、小規模保育室の配置が
  要件を満たすかを**必ず目視確認**する

| メッセージ | 原因 | 対処 |
| --- | --- | --- |
| `職員・対象日・時間帯のいずれかが空です。入力条件を確認してください。` | 職員・日付・時間帯が空 | データを投入する |
| `貪欲法による暫定シフトを生成しました（最適解ではありません）。` | 1 パス目・2 パス目とも解なし、またはモデル構築失敗 | 6.1 の配布前チェックリストをそのまま適用する |
| `PuLP では解なし。貪欲法による暫定シフトを生成しました` | 1 パス目と 2 パス目ともに解なし | `--time-limit` を上げる。3.1 節の前提条件を確認する |
| `モデル構築に失敗しました: {エラー}` | モデル構築中の例外 | エラーメッセージを読む |
| `配置基準を満たせませんでした。需要 > 供給 となる時間帯は N 件です` | 人手が足りない | 職員を追加するか、園児数を再確認 |
| `配置できる人時が 0 です。職員の契約時間帯が園の開所時間・必要人員の時間帯と 1 分も重なっていません。` | 契約時間帯と開所時間が不一致 | 契約の始業・終業時刻、園の開所時刻を確認する |

**終了コード**（`shiftai solve`）:

| コード | 条件 |
| ---: | --- |
| 0 | BLOCKER なし |
| 1 | 入力エラー / 求解失敗 |
| 2 | BLOCKER が 1 件以上（`--strict` の指定は不要） |
| 3 | BLOCKER は 0 だが WARNING が 1 件以上、かつ `--strict` 指定時 |

**運用上の使い方**: CI や自動化に組み込むなら `--strict` を付ける。
付けない限り WARNING（要調整）は終了コードに影響しないので、
自動化した場合は 3 も返されることを確認する。

### 5.2 よくある状況の切り分け

#### 症状: シフトが組めない（人員不足のメッセージが出る）

**原因**: 必要人時が契約時間合計を超えている。

**切り分け**:

1. `requirements.csv` の「必要人員」列の合計を取る
2. `staff.csv` の「週契約時間」列の合計を取る
3. 前者が後者より大きければ**構造的に不足**。人員の検討に入る
4. 前者が後者以下なら**配置の問題**。`shift_matrix.csv` で特定の時間帯に偏っていないか確認

**対処**: 職員数の増員、登降園時間の調整、延長保育の縮小。

#### 症状: 同じ職員に勤務が集中している

**原因**: 他の職員が配置できない（契約時間帯の制限、希望休、資格不足）。

**切り分け**: `payroll.csv` の「総勤務時間」列で最大と最小を確認する。
`CONSECUTIVE_DAYS` 警告があれば、連続出勤日数を確認する。

**対処**: 他の職員の契約時間帯や希望休を見直す。

#### 症状: 法令違反が出続ける

**原因**: 人手が足りない、基準が厳しい、開所時間が長い。

**切り分け**:

1. `violations.csv` の「内容」列を読む
2. 該当時間帯の必要人数と配置人数を比較する
3. 職員追加・基準変更・時間設定変更のいずれかで対応する

#### 症状: 貪欲法に落ちる

**原因**: `--time-limit` が短すぎる、または人員が構造的に足りない。

**切り分け**: `SolveResult.stats` の `solver_status_pass1` と `solver_status` を読む。

**対処**:

- `--time-limit` を 60 秒以上に上げる
- 人員が構造的に足りない場合は人員の検討に入る

## 7. まとめ

1. **原則**: 法令違反が残ったシフトは配らない。園長の責任で最終確認する
2. **前提条件**: 必要人時と契約時間合計を比較し、足りているかを確認する
3. **早朝・延長**: 需要の急変を想定し、代替措置の期限を確認する
4. **連続勤務**: `CONSECUTIVE_DAYS` 警告を確認し、職員の健康に配慮する
5. **複数保育室**: 本ツールは区別しない。手動調整または園長管理
6. **障害時**: 5.1 節の表で原因を特定し、3.1 節で前提条件を再確認する
7. **記録**: 作成者・確認者・確認日・例外理由を記録し、1 年間保管する

---

**本ツールは「シフトのたたき台」である。最終的な責任は園長にある。**
