## 2. 案1 — 勤務ブロックを「1日1塊＋休憩1回」にハード化する

### 2.1 何を変えるか

現状 `solver.py:480-481` は `_add_block` を **ソフトペナルティ**（重み
`max(break_conflict_penalty=50, 10×overstaff_penalty=10) = 50`）で呼ぶ。
配置不足の罰（`shortfall_penalty=1000`）のほうが重いので、**人が足りないと必ず
「往復勤務」が選ばれる**。実測で 109/115 職員日に穴が出たのはこれが原因。

以下を **ハード制約** にする。

| 制約 | 内容 | 根拠 |
| --- | --- | --- |
| D1 | 1職員1日の**在勤（勤務＋休憩）は高々1つの連続ブロック** | 現場では出退勤は1回だけ |
| D2 | **休憩は高々1つの連続ブロック**、かつ**勤務の前後に1セル以上**必要 | 始業直後に休憩／終業直前に休憩は業務上ありえない |
| D3 | 勤務ブロックと次の勤務ブロックの間には **最低 `MIN_CONTIGUOUS_DUTY_MINUTES` 分の下班** | 短時間の穴（回家→往復）は運用不能 |

### 2.2 ステップ分解

| # | ファイル | 内容 |
| --- | --- | --- |
| S1-1 | `config.py` | `MIN_CONTIGUOUS_DUTY_MINUTES = 120` / `SPLIT_DUTY_BLOCK_PENALTY` 追加 |
| S1-2 | `solver.py` | `_add_block` に `hard: bool = False` を追加。既定値は従来挙動。`_hard_le` を使う分岐を明示 |
| S1-3 | `solver.py` | `_add_duty_block(ctx, duty, brk, tag, n, *, hard, obj, weights, commute_min)` を新設。D1/D2/D3 の式を作る |
| S1-4 | `solver.py` | `_build_cells` の 480/481 行を `_add_duty_block` 呼び出しに置換 |
| S1-5 | `relaxation.py` | `RelaxLevel.RELAX_HOURS`（L3）で D1/D2 を**ソフト化**。`relaxed_constraint_labels` に 2 行追加 |
| S1-6 | `diagnostics.py` | `CONSTRAINT_GROUPS` に `duty_block` グループ追加（IIS で外せるように） |
| S1-7 | `docs/02` | §14.2 の `drop_groups` キー表に `duty_block` を追記（doc 契約テスト対策） |

### 2.3 式

`duty_i = w_i + b_i`、`brk_i = b_i`、`w_{-1} = duty_{-1} = 0`

```
# ブロック開始フラグ
s_i     >= duty_i - duty_{i-1}        (∀i)
bstart_i >= brk_i - brk_{i-1}          (∀i)

# D1: 在勤は1ブロック（ハード）
Σ s_i <= 1

# D2: 休憩は1ブロック、かつ勤務を挟む（ハード）
Σ bstart_i <= 1
has_brk ∈ {0,1}
Σ brk_i <= M * has_brk                M = n
Σ brk_i >= has_brk
Σ w_i   >= Σ brk_i + 2 * has_brk

# D3: 勤務ブロック間の下班（ハード・ソフト両モード）
#   勤務ブロック k と k+1 の境界に通勤用の空白を要求する。
```

`capture_specs()` は `prob.constraints` のスナップショットなので、
S1-3 の行はすべて `ctx.prob` に**名前付きで**追加する。

### 2.4 影響と緩和

- **feasible が konstru的に不可能になる可能性がある**。緩和 3 段目 (`RELAX_HOURS`) で
  D1/D2 をソフトに戻し、貪欲法フォールバックも（非配置対象者は除く）連続ブロックを生成するため
  最悪でも現場 Somehow 使える出力を得る。
- `snap_to_patterns`（`solver.py:2719`）は境界をパターンの境界へ寄せるため連続性を壊さない。
  壊れる場合は `snap_to_patterns` 後に `_normalize_duty_blocks` で連続化する（`--no-pattern-snap` 相当）。

### 2.5 テスト（S1-T）

`tests/test_duty_block_constraints.py`（新規）:

1. 3職員×1日×6時間帯で、`solve_shift` の結果が**全職員日 w/b の在勤が1連続ブロック**
2. 休憩は必ず連続1ブロック
3. 休憩の前後に勤務がある
4. 勤務ブロック間の空白が `MIN_CONTIGUOUS_DUTY_MINUTES` 以上
5. `relaxation=RELAX_HOURS` ではソフト化され、解が求まること
6. `drop_groups={"duty_block"}` で制約が外れること（IIS 診断の契約）
7. `verify_solution(ctx)` が新制約を違反として検出すること（fail-closed 維持）
8. 回帰: `tests/test_solver.py` の既存全テストが通ること

## 4. 案3 — 7日を超える計画と、診断メッセージの正確化

### 4.1 週分割モード

`solve_shift_chunked` を新設。計画期間を `weekly_periods` で分割し、
前の週の確定セルを `fixed_assignments` に固定して次の週を解く。

```
for window in weekly_periods(days):
    result_i = solve_shift(children, staff, table_i, prefs, fixed=acc_fixed, ...)
    acc_fixed |= result_i の確定
    統合
```

| # | ファイル | 内容 |
| --- | --- | --- |
| S3-1 | `solver.py` | `solve_shift_chunked(...)` 新設。`stats["chunked"]=True`、`stats["chunks"]=N` |
| S3-2 | `diagnostics.py` | `diagnose(..., solver_status=...)` に引数追加。供給が足りているのに infeasible のとき、**制約_groups を当てずに**「時間制限内で探索しきれなかった」と書く |
| S3-3 | `ui/tab_solve.py`, `ui/sidebar.py` | 「週ごとに分けて作成」トグル。分割実行の進捗表示 |
| S3-4 | `__main__.py` | `--chunk-weekly` オプション |

### 4.2 診断メッセージの分岐（S3-2）

| 条件 | 出力 |
| --- | --- |
| `rows` がある（時間帯の供給不足） | 従来どおり `STAFF_SHORT` / `QUALIFIED_SHORT` / `HOURS_SHORT` |
| `rows` がなく `need_h > supply_h` | 従来どおり `HOURS_SHORT` |
| `rows` がなく `need_h <= supply_h` かつ `solver_status` が **Infeasible 確定** | 従来どおり「休園日・週所定出勤日数・最低休息時間などが決め手」＋ IIS 誘導 |
| `rows` がなく `need_h <= supply_h` かつ `solver_status` が **Not Solved / 時間切れ** | **新メッセージ**:「時間帯ごとの供給は足りていますが、時間制限内に実行可能解を探索しきれませんでした。計画期間を週ごとに分ける・勤務パターンを有効にする・時間帯の粒度を60分に粗くする・PuLP の時間上限を延ばす のいずれかを試してください。」 |
