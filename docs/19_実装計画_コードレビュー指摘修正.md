## 3. WP の詳細

### RV-1: MILP の目的関数・制約の健全性（P0）

#### 背景

`src/shiftai/solver.py` の目的関数・制約に、実運用上のシフトを歪める欠陥がある。
いずれも「実行不能」ではなく「見かけ上解けているが品質・整合性が崩れる」タイプであり、
fast 全套が緑のまま潜在化している。

#### RV-01: 通勤ペナルティの初回ブロック誤罰（`solver.py:679-718`）

**現状**

`_add_commute_penalty` は各 `i` について

```
slack_i >= duty_i - Σ(duty_j for j in [i-reach, i))
```

を課し、`slack_i` に `split_duty_penalty`（既定 3000）を掛ける。
`i=1` で `duty_0=0, duty_1=1` のとき `window=[duty_0]` となり `slack_1=1`。
つまり **7:30 開始などの正当な「初回ブロック」が 1 件あたり 3000 罰せられる**。
これは `shortfall_penalty`（既定 1000）より重いため、2 パス目（soft coverage）では
「未配置」が選ばれ、配置不足を招く。

**最小再現（PuLP、CBC）**

```
start@0 (11110000): 0.0
start@1 (01110000): 3000.0   <-- 初回ブロックなのに罰金
start@4 (00001110): 3000.0
mid gap (11011000): 0.0
```

**修正方針**

「先行して在勤があったか」を表す 0/1 変数 `prior_i` を 1 職員あたり O(n) で導入し、
初回ブロックを罰しない。

```
prior_0 = 0
prior_i >= prior_{i-1}          (i >= 1)
prior_i >= duty_{i-1}
prior_i <= prior_{i-1} + duty_{i-1}

slack_i >= duty_i - Σ(window) - (1 - prior_i)
```

- `prior_i = OR(duty_0..duty_{i-1})` を O(n) の制約で表現する。
- `prior_i` が 0（先行在勤なし）のとき `slack_i >= duty_i - Σ(window) - 1` となり、
  0/1 変数の範囲では `slack_i=0` に落ちる。
- `prior_i=1` のときは従来どおり「在勤ブロックの再開」だけを罰する。

**注意**

- `prior_i` は連続変数 [0,1] でよい（上の 3 制約で 0/1 に固定される）。
- 1 職員あたり `prior` と `slack` で最大 2n 変数・3n 制約が増える。
  30 分粒度・25 スロットで 1 シフトあたり約 75 制約。
  求解性能への影響は RV-15 と合わせて実測する。
- `allow_split=True`（緩和 L3）の経路では D4 自体を課さないため変更不要。

|---|---|---|
| T1 | `tests/test_duty_block_constraints.py` に追加 | `duty = {0:0, 1:1, 2:1, ...}`（初回ブロックがスロット 1 開始）で目的関数が 0 であること。既存の `test_通勤ペナルティは長い下班の後の出勤を罰する` は「0 開始→再開」で 3000 になることを維持 |
| T2 | 同上 | `duty = {0:1, 1:0, 2:0, 3:0, 4:1}`（長い下班を挟む再開）で 3000 になること |

#### RV-02: `_qualified_items` の資格判定（`solver.py:1007-1043`）

**現状**

`_qualified_items` は `Role.HOIKUSHI` と `member.is_nurse`（= `Role.KANGSHI`）だけを
数え、次の 2 点を無視する。

1. `StaffingStandard.qualified_extra_roles`（例: 認可外プリセットの `{KANGSHI}`）
2. `nurse_as_qualified_cap` が 2 以上のときの上限（常に 1 名分しか数えない）

一方、`domain.qualified_count`（`domain.py:537-570`）は
`qualified_extra_roles` を分子に含め、`nurse_as_qualified_cap` を上限として
看護師を数える。同じ「必要保育士数」でも solver と検査器で結論が食い違う。

**修正方針**

`_qualified_items` を次の 3 分岐に整理する。

```python
nurse_cap = standard.nurse_as_qualified_cap if standard is not None else 0
extra_roles = standard.qualified_extra_roles if standard is not None else frozenset()
items: list[object] = []
nurse_items: list[object] = []
for member in staff:
    var = ctx.work.get((member.staff_id, day, idx))
    if var is None or _is_zero(var):
        continue
    if member.has_role(Role.HOIKUSHI):
        items.append(var)
    elif set(member.roles) & extra_roles:
        items.append(var)  # 比率の分子にそのまま算入
    elif nurse_cap > 0 and member.is_nurse:
        nurse_items.append(var)

if not nurse_items or nurse_cap <= 0:
    return items
if nurse_cap >= len(nurse_items):
    return items + nurse_items

# 上限付きのみなし保育士: used = min(nurse_cap, Σ nurses)
used = pulp.LpVariable(
    f"nurse_used_{day.isoformat()}_{ctx.prob.name}_{idx}",
    lowBound=0,
    upBound=nurse_cap,
    cat=pulp.LpContinuous,
)
ctx.prob += used <= _linear([(v, 1) for v in nurse_items])
return items + [used]
```

- `used` は `Σ items >= need_q` の左辺にのみ現れるため、ソルバは必要量まで
  `used` を最大化する。`used <= Σ nurses` と `used <= nurse_cap` により
  実効値は `min(nurse_cap, Σ nurses)` になる。
- `qualified_extra_roles` と `nurse_as_qualified_cap` は
  `StaffingStandard.__post_init__`（`domain.py:800-804`）で排他なので、
  上の `elif` で両立しない。
- 保育士と看護師を兼任する職員は `has_role(HOIKUSHI)` で先に拾い、1 名として数える。

#### RV-03: 対称性破りの署名不備（`solver.py:1401-1467`）

**現状**

`_staff_signature` は契約・希望だけを署名に使い、`skills` / `assigned_class_id` /
`can_open` / `can_close` / `can_lead` / `is_placeable` を除外している。
これらは `solver_core/constraints/classrooms.py:58-95,106` で制約に使われるため、
「同一契約だが非交換」な職員に `hours[a] <= hours[b]` を課し、
最適解の切断・実行不能を招く。

**修正方針**

- `_staff_signature` に次を追加する。
  - `frozenset(st.skills)`
  - `st.assigned_class_id`
  - `st.can_open`
  - `st.can_close`
  - `st.can_lead`
  - `st.is_placeable`
- 固定割当（`fixed_assignments`）はシフトごとに異なるため、
  `_add_symmetry_breaking` に `fixed` を渡し、
  `fixed` が空でない場合は **対称性破りを適用しない**（安全側）。
  または職員ごとに固定セルの集合を署名へ追加する。
- 署名が細かくなるほどグループが小さくなり、対称性破りの効果は下がるが、
  正しさは保たれる。

#### RV-04: `PART` / `BUNKIN` への休憩不付与（`solver.py:1187-1194`）

**現状**

`is_part_short` に `employment_type in (PART, BUNKIN)` が含まれ、
`eff_break = 0` となる。`daily_hours=8` の短時間職員でも休憩変数が作られず、
`gap_analysis` が `BREAK_INSUFFICIENT`（BLOCKER）を検出する。
つまり **solver が違反を製造している**。

**修正方針**

`is_part_short` から雇用形態の条件を外し、実労働時間だけで判定する。

```python
is_part_short = st.contract.daily_hours is not None and st.contract.daily_hours <= 6.0
```

- `_break_slots`（`solver.py:1160-1164`）は `cap_min <= 6*60` で 0 を返すため、
  6 時間以下の契約では従来どおり休憩なしになる。
- 8 時間契約の `PART` には法定 45 分（8 時間超なら 60 分）が付く。

#### RV-05: 休憩を契約上限から算出（`solver.py:1181-1194`）

**現状**

`cap_min = _daily_cap_minutes(st.contract)` を使い、`eff_break` を
`cap_min` ベースで決める。契約上限が 8 時間でも実労働が 4 時間なら、
法定上不要な 45 分休憩を強制する。

**修正方針**

- `eff_break` の判定を「契約上限」ではなく「実際の勤務時間」に近づける。
  1 日単位の勤務時間はモデル変数であり静的に分からないので、
  当面は **契約の `daily_hours`**（1 日の標準勤務時間）を優先し、
  無い場合のみ `cap_min` を使う。
- より厳密には「勤務スロット数 × 粒度」で事後判定する二段構えにする。
  1 段目で休憩変数を張り、2 段目で不足分を `break_deficit_penalty` で罰する
  既存の枠組みを使う（`_add_breaks` の `brkdef` は既に不足分を罰している）。
- 変更は `eff_break` の初期値に限定し、実際の違反は `gap_analysis` に委ねる。

#### RV-06: 深夜終端スロットの比較（`domain.py:250-255,948-949`）

**現状**

- `Slot.overlaps`（`domain.py:250-255`）は midnight-end のとき
  `to_minutes(end) > self.start_minutes` で比較する。
  `end=00:00`（=24:00）は `to_minutes(00:00)=0` なので、
  `[22:00,24:00)` と `[23:00,00:00)` が非重複と判定される。
- `is_standard_time`（`domain.py:948-949`）は
  `slot.end <= self.standard_time[1]` で、midnight-end の `slot.end=00:00` を

#### RV-15: `per_chunk_time` 下限が予算を超過（`monthly.py:309,318`）

  ```python
  if remaining_budget >= 20 * waves:

  ```

### RV-5: データ取込の防御（P0/P1）

#### RV-23: `parse_time` の午前午後・24時丸め（`data_loader.py:460-510`）

**現状**

- `午前` / `午後` を除去するだけで +12 時間しない。`午後5時` → `05:00`。
- 小数 `frac >= 0.99965` で `total=1440` → `time(hour=24)` の `ValueError`。
- `load_children` / `load_staff` の行ループで未捕捉のため、1 行の不正で全体が落ちる。

**修正方針**

```python
def parse_time(value: Any) -> time | None:
    ...
    if isinstance(value, int | float) and not isinstance(value, bool):
        frac = float(value)
        if 0.0 <= frac < 1.0:
            total = int(round(frac * 24 * 60))
            total = min(total, 24 * 60 - 1)  # 1440 -> 1439
            return time(hour=total // 60, minute=total % 60)
        return None
    text = _digits(_text(value))
    ...
    pm = "午後" in original_text
    am = "午前" in original_text
    text = text.replace("時", ":").replace("分", "").replace("午前", "").replace("午後", "")
    ...
    if pm and hour < 12:
        hour += 12
    elif am and hour == 12:
        hour = 0
    ...
```

- `_text(value)` の生値を別途保持して `午前` / `午後` を判定する。
- `load_children` / `load_staff` の `parse_time` 呼び出しを `try/except (ValueError, TypeError)` で囲み、
  例外時は `LoadIssue("error", ...)` を追加して `continue` する。

### RV-6: 出力・エクスポート・CLI（P1/P2）

#### RV-26: 深夜時間集計の粗さ（`exporter.py:379-380`）

**現状**

`slot.start >= 22:00 or slot.end <= 05:00 or slot.overlaps(22:00, 23:59)` で
`slot.minutes` を全部深夜に加算する。`21:00-23:00` を 120 分、
`04:00-06:00` を 0 分と数える。

**修正方針**

- 深夜帯 `[22:00, 24:00)` と `[00:00, 05:00)` との重なり分だけを計算する。
- `Slot` の `start_minutes` / `end_minutes`（midnight-end は 1440）を使い、
  ```python
  def _night_minutes(slot) -> int:
      start = slot.start_minutes
      end = 24 * 60 if slot.is_midnight_end else to_minutes(slot.end)
      late = max(0, min(end, 24 * 60) - max(start, 22 * 60))
      early = max(0, min(end, 5 * 60) - max(start, 0))
      return late + early
  ```
- `night_min += _night_minutes(slot)` にする。
