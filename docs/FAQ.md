# よくある質問 (Q&A / FAQ) - nushift / shiftai & open-hoikuict

保育所の職員配置基準連動型シフト自動作成エンジン **nushift (shiftai)**、および保育ICTプラットフォーム **open-hoikuict** との統合に関するよくある質問と回答です。

---

## 1. プロジェクトの関係と統合アーキテクチャ

### Q. nushift と open-hoikuict はどのような関係ですか？
**A.** 
- **nushift (shiftai)** (`E:\nushift\nushift`): 数理最適化（MILP / HiGHS・CBC ソルバー）を用いて、保育法令配置基準（厚労省および自治体基準）を満たす勤務割を自動作成するソルバーコアエンジンです（Python パッケージ / CLI / Streamlit UI）。
- **open-hoikuict** (`C:\Users\user\openict\open-hoikuict`): 園児台帳、登降園、日次連絡、保護者ポータル、請求、MFA等を備えたオープンソース保育ICT Web プラットフォームです。
- **統合運用**: open-hoikuict に nushift を `vendor/nushift/shiftai` として完全統合し、現場でのセル微調整・ピン留め・労基法承認ゲート・配置割れ検知・帳票エクスポート（Excel / CSV / ZIP / 監査ログ連携）をワンストップで提供します。

自動同期スクリプト `scripts/sync_nushift_vendor.py` と整合性検証スクリプト `scripts/check_vendor_integrity.py` により、nushift 本体の最適化ロジックと open-hoikuict 側のソルバー挙動は常に 100% 同期・整合性が保証されます。

## 2. 最適化ロジックとソルバー（週単位および月次一括対応）

### Q. 月単位（30日〜31日間）でまとめてシフトを計算できますか？
**A. はい、完全に対応しています（2段階階層的最適化エンジン搭載）。**  
従来の単一詳細スロット MILP では、30日分を一括計算すると変数・制約が数万件に爆発しタイムアウトする課題がありました。フェーズ2において、以下の**「2段階階層的最適化（Hierarchical MILP: `shiftai.monthly`）」**を導入しました。

1. **Stage 1 (月間日次パターン大域最適化)**:  
   全日（30日間）について、職員ごとの勤務パターン（日勤・早番・遅番・半日等）と公休（OFF）を MILP で大域決定します。前月末の連勤履歴バッファを考慮した連続勤務上限（5連勤以下）や、月間所定公休目標（月8日等）の厳密遵守、パート職員の契約時間遵守を瞬時に確定します。
2. **Stage 2 (週スライス単位 30分スロット詳細配置 & 休憩スタッガー最適化)**:  
   Stage 1 で確定した公休や勤務パターンの時間外スロットを OFF 固定し、探索空間を 90% 以上削減。週スライス（7日単位）で厚労省配置基準充足と同時休憩スタッガーを詳細最適化します。

これにより、30日間の月次一括シフトも十数秒〜数十秒で確実に適法かつ高品質な実行可能解（FEASIBLE / OPTIMAL）として出力されます。現場の運用に合わせて「週単位（7日間詳細）」と「月次一括（2段階階層的）」を自由に選択可能です。

### Q. 推奨ソルバーは何ですか？ CBC と HiGHS の違いは？
**A. 高速な「HiGHS」の利用を推奨します（環境に応じて自動選択されます）。**  
- **HiGHS**: 最新のオープンソース高性能 MILP ソルバーです（`highspy` 経由）。従来の CBC に比べ 2〜10 倍高速で、複雑な配置制約や月次一括最適化を極めて高速に求解します。環境に存在する場合は自動で最優先選択されます。
- **CBC**: PuLP に標準同梱されている安定した MILP ソルバーです。HiGHS が未インストールの環境でも自動的にフォールバックとして機能します。
- `select_optimal_solver()` および `solver_diagnostic_info()` により、実行環境のソルバー検出とヘルスチェックが常時行われます。

### Q. 「最適解」ではなく「実行可能解」と表示されますが、問題ないですか？
**A. 問題ありません。保育現場の実務上、十分かつ高品質なシフトです。**  
本番規模の複雑な制約（年齢別比率、資格要件、契約時間、連続勤務、希望休等）のもとでは、数学的に「これ以上良い解がない（最適性）」を厳密証明するには膨大な時間がかかります。そのため、時間制限（既定30〜60秒）内で**「法令・契約・希望休のハード制約をすべて満たした解（実行可能解: Feasible）」**を取得して出力します。

## 3. セル編集・ピン留め (Pinning) と再計算

### Q. 画面上でシフトを手動調整した後、「再計算」を実行すると変更が消えてしまいますか？
**A. 消えません。「ピン留め」機能を使用してください。**  
修正したいコマを「ピン留め (is_pinned = True)」に指定すると、ソルバーに `fixed_assignments` として渡されます。再計算を実行してもピン留めされたセルは固定値として扱われ、残りの未ピン留めセルのみが再最適化されます。

### Q. 労働基準法違反（1日10時間超など）のシフトができてしまうことはありますか？
**A.** ソルバーは1日最大10時間（法定労働時間8h×1.25）のハード制約をかけていますが、手動編集によって過密勤務が生じたり、深刻な職員不足下で BLOCKER 違反が発生する場合があります。  
open-hoikuict では、**労働基準法第32条違反（1日10h超）または保育士不足の BLOCKER 違反が1件でもある場合、園長承認が 409 Conflict でブロック** されます。

## 4. デザインシステムと UI / 帳票の統一

### Q. 画面や帳票の配色・デザインルールはどうなっていますか？
**A. open-hoikuict と nushift で共通の Emerald / Slate デザインシステムに完全統一されています。**  
- **勤務 (Work)**: Emerald `#059669` (文字色: `#064E3B`)
- **休憩 (Break)**: Amber `#D97706` (文字色: `#78350F`)
- **公休 (Off)**: Slate `#F1F5F9` (文字色: `#475569`)
- **不足 (Shortfall)**: Rose `#E11D48` (文字色: `#881337`)
- **超過 (Over)**: Indigo `#4F46E5` (文字色: `#312E81`)
- **ピン留め (Fixed)**: Purple `#7C3AED` (文字色: `#4C1D95`)

UI（Streamlit / Tailwind CSS）から帳票（Excel / PDF / CSV）まで一貫したカラーパレットと記号表現（日・早・遅・半・休・★）が適用されています。

## 5. 出力とエクスポート

### Q. どのようなファイル形式で出力できますか？
**A. 以下の形式に対応しています。**
- **Excel 勤務割表 (`.xlsx`)**: 職種・資格・日別合計時間・配置判定・免責文言付きの施設掲示・印刷用フォーマット。
- **CSV 勤務割表 (`.csv`)**: Excel で文字化けしない BOM 付き UTF-8 形式。給与連携・データ分析用。
- **ZIP 一括パッケージ (`.zip`)**: 園児台帳、職員契約、希望休、シフト結果、監査ログをワンクリックでまとめてエクスポート可能。
- **iCalendar (`.ics`)**: Google カレンダーや iPhone カレンダーへ直接取り込めるスケジュール形式。

## 6. 免責事項

### Q. シフト自動作成の法的責任はどうなりますか？
**A. 最終的な配置確認および法的責任は、施設の管理者（園長・施設長）が負います。**  
本ツールが生成するシフトは、数理最適化と法令基準に基づく「提案」です。地域ごとのローカルルール、保育室ごとの個別事情、突発的な園児・職員の状況に応じた最終判断は、必ず人が行ってください。
