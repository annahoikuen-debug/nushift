# よくある質問 (Q&A / FAQ) - nushift / shiftai (nusoft v0.3.5)

保育所の職員配置基準連動型シフト自動作成エンジン **nushift (shiftai)**、および保育ICTプラットフォーム **nusoft (open-hoikuict) v0.3.5** との統合に関するよくある質問と回答です。

---

## 1. nusoft v0.3.5 との関係について

### Q. nushift と open-hoikuict / nusoft はどのような関係ですか？
**A.** 
- **nushift (shiftai)** (`E:\nushift\nushift`): 数理最適化（MILP / CBCソルバー）を用いて、保育法令配置基準を満たす勤務割を自動作成するソルバーコアエンジンです（Python ライブラリ / CLI / Streamlit UI）。
- **open-hoikuict** (`C:\Users\user\openict\open-hoikuict`): 園児台帳、登降園、日次連絡、保護者ポータル、請求、MFA等を備えたオープンソース保育ICT Web プラットフォームです。
- **nusoft v0.3.5**: open-hoikuict に nushift を `vendor/nushift/shiftai` として完全統合し、現場でのセル微調整・ピン留め・労基法承認ゲート・配置割れ検知・帳票エクスポートをワンストップで提供する統合プロジェクト名です。

自動同期スクリプト `scripts/sync_nushift_vendor.py` により、nushift 本体の最適化ロジックと open-hoikuict 側のソルバー挙動は常に同期されます。

## 2. ソルバーの最適化ロジックと計算

### Q. なぜ計算単位は「週（7日間固定）」なのですか？ 月単位でまとめて計算できないのですか？
**A.** 主に2つの理由があります。
1. **数理最適化の計算複雑性 (MILP)**: 
   保育所の規模（職員約28名、1日25コマ、6〜7日間）では、変数約14,000個・制約約19,000本に達します。月単位（30日以上）で一括求解しようとすると制約数が指数関数的に爆発し、時間制限内に実行可能解が得られなくなります。週単位であれば、CBC ソルバーが数秒〜30秒程度で高品質な実行可能解を導き出せます。
2. **現場運用の実態**:
   園児の急な登園・欠席予定変更や、職員の体調不良・希望休の変更に柔軟に追従するため、現場では週単位の管理が最も運用しやすいためです。

### Q. 「最適解」ではなく「実行可能解」と表示されますが、問題ないですか？
**A. 問題ありません。保育現場の実務上、十分かつ高品質なシフトです。**  
本番規模の複雑な制約（年齢別比率、資格要件、契約時間、連続勤務、希望休等）のもとでは、数学的に「これ以上良い解がない（最適性）」を厳密証明するには膨大な時間がかかります。そのため、時間制限（既定30〜60秒）内で**「法令・契約・希望休のハード制約をすべて満たした解（実行可能解: Feasible）」**を取得して出力します。

## 3. セル編集・ピン留め (Pinning) と再計算

### Q. 画面上でシフトを手動調整した後、「再計算」を実行すると変更が消えてしまいますか？
**A. 消えません。「ピン留め」機能を使用してください。**  
修正したいコマを「ピン留め (is_pinned = True)」に指定すると、ソルバーに `fixed_assignments` として渡されます。再計算を実行してもピン留めされたセルは固定値として扱われ、残りの未ピン留めセルのみが再最適化されます。

### Q. 労働基準法違反（1日10時間超など）のシフトができてしまうことはありますか？
**A.** ソルバーは1日最大10時間（法定労働時間8h×1.25）のハード制約をかけていますが、手動編集によって過密勤務が生じたり、深刻な職員不足下で BLOCKER 違反が発生する場合があります。  
nusoft v0.3.5 では、**労働基準法第32条違反（1日10h超）または保育士不足の BLOCKER 違反が1件でもある場合、園長承認が 409 Conflict でブロック** されます。

## 4. 登降園連動・配置割れギャップ検知

### Q. 登降園変更時に表示される「配置割れ警告バナー」とは何ですか？
**A.** 保護者ポータルやキオスクで園児のお迎え予定が延長されたり、急な登園が発生した場合、バックエンドの `gap_analysis.py` エンジンが自動的に当日の必要保育士数と現行シフトの配置数を突合します。  
保育士が不足する時間帯（ギャップ）が生じた場合、シフト画面に警告バナーと不足コマ数が即座に表示され、現場での速やかな追加配置や調整を促します。

## 5. 出力とエクスポート

### Q. どのようなファイル形式で出力できますか？
**A. 以下の形式に対応しています。**
- **Excel 勤務割表 (`.xlsx`)**: 職種・資格・日別合計時間・配置判定・免責文言付きの施設掲示・印刷用フォーマット。
- **CSV 勤務割表 (`.csv`)**: Excel で文字化けしない BOM 付き UTF-8 形式。給与連携・データ分析用。
- **iCalendar (`.ics`)**: Google カレンダーや iPhone カレンダーへ直接取り込めるスケジュール形式。

## 6. 免責事項

### Q. シフト自動作成の法的責任はどうなりますか？
**A. 最終的な配置確認および法的責任は、施設の管理者（園長・施設長）が負います。**  
本ツールが生成するシフトは、数理最適化と法令基準に基づく「提案」です。地域ごとのローカルルール、保育室ごとの個別事情、突発的な園児・職員の状況に応じた最終判断は、必ず人が行ってください。
